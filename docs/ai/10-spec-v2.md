상태: 초안 (AI 작성, 사용자 검토 대기). 2026-09-24.

## 1. 원칙 (모든 설계의 근거)

1. **문서에서 실행하고, 실행이 문서가 된다.** 위키 노트, 이력서, 코딩 과업은 전부 "페이지"다. 페이지에 요청을 보내면 에이전트가 새 세션으로 돌고, 결과·결정·읽은 파일·비용이 그 페이지에 남는다.
2. **진실은 파일이다.** 앱 상태 DB가 없다. 앱이 보여 주는 모든 것은 디스크의 파일과 1:1이고, 어떤 편집기로 열어도 같은 것이다.
3. **앱은 추측하지 않는다.** 표시되는 것은 사실(확장자), 선언(설정 파일), 관찰(실제로 일어난 일)뿐이다. 감지·휴리스틱 없음.
4. **정본은 하나, 나머지는 참조.** 뷰어·실행 대상·프로젝트는 원래 있는 자리에 있고, 앱은 그 위치를 가리킨다. 복사본은 "고정(pinned)"이라고 명시된 캐시뿐이다.
5. **모든 부작용은 core 하나를 지난다.** git·게시·실행은 사용자 버튼이든 에이전트든 같은 경로로 실행되고 같은 정책을 따르고 같은 기록에 남는다.
6. **한 동작.** 사용자가 누르는 것은 "보내기" 하나. 모델 선택, 승격, 대체, 머지, 게시는 정책이 한다. 막힐 때만 페이지에서 묻는다. 결과 옆에는 "되돌리기".

## 2. 디스크 레이아웃

### 2.1 전역 `~/.madang/`
```
profile.md      기억: 나 (언어, 금지 규칙, 커밋 규칙, 취향)          ← 에이전트가 읽음
config.yaml     설정: 앱 동작 (기본 정책, 도구 경로, 라우팅 표)        ← 앱이 읽음
viewers.yaml    등록부: 뷰어 참조 목록 (§5)
cache/          pinned 뷰어 사본, 해시 이름
```

### 2.2 프로젝트 `<프로젝트>/.madang/`
```
brief.md        기억: 이 프로젝트 (목적, 스택, 규칙, 하지 말 것)      ← 에이전트가 읽음
config.yaml     설정: runs, 정책(자동 머지·게시), 뷰어 링크 덮어쓰기   ← 앱이 읽음
pages/<id>/
  page.md       페이지 본문 (요청·실행·결과 블록이 쌓임)
  ledger.md     기억: 이 페이지 (머리부: 결정·할 일·산출물·읽은 파일; 본문: 요약)
  runs/<n>.jsonl 실행 원본 로그 (스트림 그대로, 앱이 접어서 보여 줌)
viewers/        프로젝트 전용 뷰어 (전역과 같은 규격, 같은 이름이면 이것이 우선)
```
- **프로젝트 = 폴더.** git 유무는 기능 유무(§6)만 정한다. 위키 볼트, 이력서 폴더, 코드 저장소가 모두 프로젝트다.
- **워크트리**: git 프로젝트의 코딩 페이지는 열릴 때 `<프로젝트>.wt/<page-id>/`에 워크트리를 만들고 그 안에서 에이전트·터미널이 돈다. 페이지 폴더는 메인 체크아웃의 `.madang/`에 있어 워크트리를 지워도 남는다. 워크트리 안에서 `.madang/`을 만들지 않는다.
- `.madang/`를 커밋할지는 `config.yaml`의 `track: true|false`(기본 false → `.git/info/exclude`에 추가).
- 기억(md)과 설정(yaml)은 섞이지 않는다. 에이전트는 md 셋만 받는다. 에이전트가 yaml을 바꾸면 그것은 부작용이므로 core CLI를 통해 하고 Ledger에 남는다.

### 2.3 메모리 이름
| 층 | 이름 | 파일 | 형식 |
|---|---|---|---|
| 나 | **Profile** | `~/.madang/profile.md` | md + 머리부 |
| 프로젝트 | **Brief** | `<프로젝트>/.madang/brief.md` | md + 머리부 |
| 페이지 | **Ledger** | `<프로젝트>/.madang/pages/<id>/ledger.md` | md + 머리부(decisions/tasks/artifacts/reads) |

- 호출당 입력 = Profile + Brief + Ledger + 요청 + 요청이 링크한 파일. 이 밖은 없다. 각 부분의 토큰 수를 core가 세어 실행 블록에 남긴다.
- Ledger 상한 2,000토큰. 검사기가 넘치면 거부하고 요약을 요구한다(기존 state 검사기 계승).
- 앱의 "메모리" 탭은 이 셋을 항상 같은 순서로 보여 준다. 머리부는 폼, 본문은 md 뷰어, "원문" 토글.

## 3. core (Python, 단일 서비스)

기존 core를 계승한다(러너·라우터·검사기·OpenAPI·LangGraph 흐름·A0 검증). 바뀌는 것만 적는다.

| 모듈 | 역할 | 변경 |
|---|---|---|
| `memory` | Profile/Brief/Ledger 읽기·검사·토큰 계수 | state→ledger 이름, 경로 §2 |
| `router` | routes.yaml 규칙, 승격, 대체 | 유지. 페이지 `kind`(doc/code/chat)가 규칙 입력 |
| `runner` | `claude -p` / `codex exec` 새 세션, stream-json | 유지 |
| `recorder` | 실행 결과를 page.md 블록 + ledger 머리부 + runs/*.jsonl에 기록 | 신규(기존 결과 쓰기 통합) |
| `git` | status/stage/commit/branch/worktree/merge/push/pull/log/diff | 신규. **core만 git을 실행한다** |
| `publish` | 렌더러로 정적 사이트 생성 → 대상(gh-pages, 폴더, 후에 호스팅) | 신규 |
| `viewers` | 등록부 읽기, 감시, 해시, pinned 캐시, 스키마 검사 | 신규 |
| `runs` | config `runs:` 실행, 포트 관찰, 브라우저 열기 요청 이벤트 | 신규 |
| `pty` | 터미널 PTY 소유, 앱과 분리된 데몬(Orca 방식), 훅 수신 | 신규(v0.2) |
| `api` | REST + SSE. OpenAPI 계약 | 확장 |
| `policy` | config의 정책 판단: 자동 머지 조건, 자동 게시, 금지 명령 | 신규 |

- **부작용 경로**: 사용자 버튼 → api → policy → (git|publish|runs) → recorder. 에이전트 → `madang` CLI → api → 같은 경로. 에이전트 프롬프트에 직접 `git`·배포 명령 금지가 들어가고, 러너는 `git push --force`류를 deny 규칙으로 막는다.
- **되돌리기**: recorder가 모든 부작용을 역연산 가능한 형태(커밋 해시, 게시 해시, 파일 스냅샷)로 남긴다. 페이지 결과의 "되돌리기"는 이 기록을 정확히 되감는다.
- **한 동작 흐름**: send → route → run → recorder → policy(테스트 통과 ∧ 충돌 없음 → merge; 문서 변경 → publish) → recorder. 정책이 거부하면 페이지에 "묻는 블록"이 생기고 거기서만 사람이 답한다.

## 4. 앱 (KMP + Compose, 데스크톱 우선)

기존 KMP 코드를 계승한다(3열, 탭, 프로젝트→페이지, 온보딩, core 연결). 바뀌는 것만.

### 4.1 배치
```
왼쪽 (Notebook Navigator식)  | 가운데 탭·분할                       | 오른쪽 탭
프로젝트 → 페이지 카드         | 문서 · 터미널 · 채팅 · 브라우저 · 디프 · 데이터 | 지금 · 파일 · 메모리 · git · 포트 · 기록
(상태 글리프, 미리보기,        |                                       |
 브랜치, 미읽음 굵게)           | [활성 탭에게…]              [보내기]    |
```
- **가운데 탭은 여섯 종류로 고정.** 무엇을 열어도 이 중 하나. 종류는 파일 확장자(사실)와 열기 요청(선언)으로만 정해진다.
  - `.md` → 문서 / `.json`·`.yaml`·`.csv` → 데이터 / `.html`·URL → 브라우저 / PTY → 터미널 / kind=chat 페이지 → 채팅 / git diff → 디프 / 그 외 파일 → 문서 탭의 코드 보기(편집 없음, "외부 편집기로 열기").
- **입력창은 하나**, 대상은 활성 탭. 문서 탭 = 그 페이지에 요청, 채팅 탭 = 한 턴 = 새 세션 호출 하나(페이지 블록으로 누적), 터미널 탭 = 그 PTY에 입력.
- **오른쪽 탭**
  - 지금: 모든 프로젝트의 진행 중 실행, 진행 로그, 구독 사용량(~/.claude·~/.codex 파서), 누르면 마지막 호출의 입력 구성.
  - 파일: 워크트리(또는 폴더) 트리. `.madang/`은 맨 위에 접힌 채로. 배지는 `runs:`에 선언된 것에만 **실행**. 렌즈 필터: 전체 / 이 페이지 / 변경됨.
  - 메모리: Profile / Brief / Ledger.
  - git: git 프로젝트에만. 변경 파일·스테이지·커밋·브랜치·워크트리(어느 페이지가 쓰는지)·로그·푸시/풀. 없으면 "git 시작" 하나.
  - 포트: 열린 포트(관찰). 항목마다 "선언으로 저장" → `runs:`.
  - 기록: 실행 목록(모델·이유·비용·결과).
- **브라우저 탭**은 KCEF WebView. 뷰어(§5)와 실행 대상(§6)이 같은 탭 종류로 열린다.
- **터미널 탭**은 WebView 안 xterm.js + core pty(Orca 구성 이식). 여기서 `claude`를 대화형으로 띄워도 되고, 훅이 상태·결과를 core로 보내 Ledger에 남긴다.
- **더블클릭 = 열기**, 항상. 파일이면 종류대로 탭, `runs:` 항목이면 실행 후 브라우저 탭.

### 4.2 렌더러
- 문서 렌더러는 JS 라이브러리 하나(`templates/_runtime` 계승). md + 머리부 + ```view``` 펜스 + 코드 + 표. **앱의 문서 탭과 publish가 같은 렌더러를 쓴다.** 로컬=웹은 이 규칙 하나로 보장한다.

## 5. 뷰어 (Viewer)

- **뷰어 = 폴더.** `viewer.json`(name, version, schema, entry) + `index.html` + 자산. 어느 프로젝트 안에 있어도 되고 그 프로젝트의 git으로 버전이 관리된다.
- **등록 = 참조.** `~/.madang/viewers.yaml`:
  ```yaml
  - name: resume/basic
    source: /abs/path/to/viewer
    follow: live | pinned
    pinned: <git commit 또는 내용 해시>   # pinned일 때
  ```
  복사하지 않는다. `live`면 core 감시가 변경을 잡아 그 뷰어를 쓰는 문서를 다시 렌더한다. `pinned`면 `cache/<해시>/`의 사본을 쓴다.
- **게시는 항상 pinned.** 게시 시점 해시가 사이트에 포함된다. 정본이 바뀌어도 게시본은 안 깨진다.
- **임베드**: 문서 안 ` ```view resume/basic data=./base.json``` `. `@<해시>`로 버전 고정 가능. 데이터 탭이 옆에 열린다.
- **격리**: 뷰어마다 sandbox iframe. 앱은 고정 토큰 집합(`--app-bg`, `--app-text`, `--app-accent`, `--app-font`, `--app-radius`)을 iframe 안으로 **주기만** 한다. 뷰어는 정의·덮어쓰기 불가. 뷰어 스타일은 자기 iframe 안에만.
- **이름 충돌**: `프로젝트/뷰어` 네임스페이스. 같은 이름 등록은 오류. 프로젝트 `viewers/`가 전역과 같은 이름이면 그 프로젝트 안에서만 우선.
- **스키마 검사**: 데이터가 `schema`에 안 맞으면 어디가 안 맞는지 보여 주고 렌더하지 않는다.
- **끊김**: source가 없으면 등록 항목이 "끊김", 문서는 데이터를 표로 대체 표시.

## 6. 실행 대상 (Runs)와 git

### 6.1 실행 대상
- 폴더 수준 실행 대상은 `<프로젝트>/.madang/config.yaml`의 `runs:`뿐이다.
  ```yaml
  runs:
    - name: 이력서 사이트
      cwd: resume/site
      command: npm run dev
      opens: http://localhost:5173
  ```
- 세 경로만 존재: (1) 확장자 규칙(`.html` 더블클릭 → 브라우저 탭), (2) 선언(`runs:`), (3) 관찰(터미널에서 열린 포트 → 포트 탭 → 클릭 시 선언으로 저장). 감지 없음.
- 에이전트가 실행 가능한 것을 만들면 `madang runs add`로 선언하는 것이 과업의 일부다. Ledger 검사기가 `artifacts`에 실행물이 있는데 `runs:`에 없으면 거부한다.

### 6.2 git
- git 프로젝트: 오른쪽 git 탭, 가운데 디프 탭, 워크트리 자동. 비git 프로젝트: "git 시작"만.
- core `git` 모듈만 git을 실행한다. 정책(`config.yaml`):
  ```yaml
  policy:
    auto_merge: {require_tests: true, require_no_conflict: true}
    auto_publish: true
    deny: ["push --force", "reset --hard", "clean -fd"]
  ```
- 앱 밖에서 한 git 조작은 다음에 git 탭을 열 때 상태로 보일 뿐이다. 앱은 해석하지 않는다.

## 7. 게시 (Publish)
- `madang publish`: 렌더러로 정적 사이트 생성(문서 + pinned 뷰어 + 데이터) → 대상. v0.1 대상은 gh-pages 브랜치와 로컬 폴더. 호스팅(구독)은 같은 산출물을 서버가 받는 것이라 렌더 경로가 같다.
- 게시 단위는 프로젝트의 `publish:` 설정(포함 경로, 도메인). 페이지 기록(`.madang/`)은 기본 제외.

## 8. 서비스 형태 (설계에만 영향, v0.x에서는 만들지 않음)
- 무료: 앱 + core + 렌더러 + 뷰어 규격 (MIT).
- 구독: 게시 호스팅(내 도메인), 원격 러너(사용자 구독으로 서버에서 실행), 팀 위키. 셋 다 core가 서버 모드로 도는 것이라 별도 코드 경로가 없다.

## 9. 살리는 것 / 버리는 것

| 살림 | 버림 |

| core 러너·라우터·검사기·OpenAPI·LangGraph·A0 검증·D23 저장 | 앱 홈 저장소, 승격, 페이지 등록부 |
| KMP 3열, 탭, 프로젝트→페이지, 온보딩, core 연결 | 4번째 열 "지금" (→ 오른쪽 탭) |
| 템플릿 런타임(→ 렌더러 + 뷰어 규격) | "템플릿 프리셋" 별도 개념 (→ 뷰어) |
| ops 오케스트레이션 | state.md 이름 (→ ledger.md), root/project 이름 (→ profile/brief) |
| Orca 이식 목록(08) 중 사용량 파서·xterm 구성·PTY 데몬·디프 주석 | 파일 트리 휴리스틱 전부 |

## 10. 모순 점검표
- 실행 대상과 뷰어는 둘 다 "선언된 것만" (원칙 3·4).
- 뷰어 정본이 프로젝트 안 → git이 곧 뷰어 버전 → pinned 해시 = 커밋 (원칙 4, §5·§6.2).
- 기억(md)/설정(yaml) 분리 → 에이전트 입력과 앱 동작이 섞이지 않음 (§2).
- 부작용은 core 한 경로 → 사용자·에이전트·정책·되돌리기가 같은 기록 (원칙 5, §3).
