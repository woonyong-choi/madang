# Madang: 경쟁 지형 심층 검토와 방향 재확인

상태: 초안 (AI 작성, 미승인)
작성: 2026-09-24
근거: Orca 제품·저장소·문서·이슈·리뷰, 오케스트레이션 도구 27종, 문서·노트북·게시·메모리·생성 UI 도구 50여 종 조사(같은 날). 수치는 조사 시점 기준.

## 0. 결론 먼저

1. **"워크트리마다 에이전트 하나를 돌리는 데스크톱 대시보드"는 이미 포화 상태다.** Orca(76k 스타, YC, 387명 기여), Herdr(37k 스타, 9월 $6M 시드), Conductor, Superset, Emdash(YC W26), cmux(26k), T3 Code(16k), JetBrains Air, 그리고 큐레이션 목록에만 150개. 자금 받은 두 곳(Terragon, Bloop/Vibe Kanban)이 이미 문을 닫았고, Cursor·ChatGPT·Claude Desktop이 같은 기능을 자기 앱에 넣고 있다. **이 층은 우리가 만들 이유가 없다.**
2. **문서 쪽 방향은 맞다. 단, "노트 앱"이 아니라 "에이전트 작업의 기록이자 실행 결과가 살아 있는 페이지"여야 한다.** 우리 차별점 다섯 가지(모델 간 자동 라우팅, 파일로 보이는 메모리, 호출별 입력 구성, 페이지가 작업 단위, 게시)를 **한 도구가 동시에** 하는 곳은 없다. 각각을 부분적으로 하는 곳은 있고, 그 부분들은 전부 벤더 종속(Claude만, OpenAI만)이거나 유료 폐쇄형이다.
3. **가장 가까운 경쟁자는 Orca가 아니라 "Obsidian + Claudian + Bases + Publish" 조합이다.** 우녕님이 화면 기준으로 고른 Notebook Navigator가 Obsidian 플러그인이라는 사실이 이를 말해 준다. 그래서 파일 형식을 Obsidian과 호환되게 잡는 것이 방어이자 유통 전략이 된다.
4. **Orca에서 가져올 것은 IDE 레이아웃이 아니라 상태 표시·알림·사용량·주석 전송 같은 "에이전트를 다루는 소소한 장치들"이다.** 아래 §4에 15개를 구체적으로 적었다.
5. **뷰 런타임은 지금 MCP Apps 표준에 맞추는 것이 좋다.** 비용은 작고, 같은 뷰가 Claude·ChatGPT·VS Code 안에서도 그려지는 이식성을 얻는다.

## 1. Orca 심층: 무엇이고 어디까지 왔나

| 항목 | 사실 |
|---|---|
| 정체 | Stably AI(YC W22, 25명)의 두 번째 제품. 2026-03-17 첫 커밋. MIT. Electron 43 + React 19 + xterm.js(WebGL) + node-pty + Electron WebContentsView(워크트리마다 Chromium 하나) |
| 규모 | 76k 스타, 5k 포크, 387명 기여, 11,400 커밋, 열린 이슈 3,000개, 릴리스 740회(v1.4.207). 주당 +6k 스타 |
| 단위 | git worktree. 모든 것이 worktree에 매달린다(터미널, 브라우저, 디프, PR) |
| 상태 감지 | 터미널 OSC 제목 + 에이전트 훅. 앱 안의 훅 서버가 단일 저장소. PTY는 별도 데몬이 소유해 앱을 닫아도 에이전트가 산다 |
| 컨텍스트·메모리 | **관여하지 않는다.** "CLAUDE.md와 AGENTS.md는 에이전트 것"이라고 문서에 명시. 세션 재개는 `claude --resume` 실행 |
| 사용량 | `~/.claude`, `~/.codex`의 디스크 상태를 읽어 5시간·일·주·Fable 주간 창을 상태바에 표시. API 호출 없음 |
| 문서 | Tiptap 마크다운 편집기(슬래시 메뉴, mermaid, 위키링크). "Share as artifact"로 md 하나를 공개 링크로 |
| 오케스트레이션 | CLI에 Run/Task/Dispatch/Worker 원시 타입. 모델 선택은 사람. 라우팅 없음 |
| 사용자 불만 | RAM(에이전트 5개면 10GB), 매일 릴리스마다 회귀, 텔레메트리 기본 켜짐, 디프 뷰 찾는 데 30분(발견성), "리뷰가 병목", "오케스트레이터라고 하지만 아무도 진짜 오케스트레이션은 못 한다"(HN) |

Orca는 **"에이전트를 위한 IDE"**를 완성도 높게, 매우 빠르게 만들고 있다. Madang이 같은 것을 만들면 3월에 시작한 25명 팀과 76k 커뮤니티를 따라잡아야 한다.

## 2. 오케스트레이션 도구 지형 (27종)

전체 표는 `reference/`에 두지 않고 여기 요약만 둔다. 다섯 축은 Madang의 차별점이다.

| 축 | 하는 곳 | 비고 |
|---|---|---|
| (a) Claude↔OpenAI 자동 라우팅 | Cursor Router(Teams 이상), Factory Router(비공개 프리뷰), Warp Oz, Amp(작업 종류별) | **전부 자사 에이전트 안에서만.** 사용자의 기존 구독 두 개를 오가는 오픈소스 라우터는 없다 |
| (b) 메모리를 파일로 보여주고 편집 | Claude Code 자체(`~/.claude/projects/<p>/memory/MEMORY.md` + 주제 파일, `/memory`), Antigravity(AGENTS.md 자동 합성), Nimbalyst(자기 상태만 md) | 서드파티 오케스트레이터 중 에이전트 간 메모리 브라우저를 가진 곳 없음. Herdr는 "공유 메모리 없음"을 명시, JetBrains Air 리뷰는 "에이전트끼리 배운 걸 모른다" |
| (c) 호출별 입력 구성 표시 | Claude Code `/context`(CLI, 요청 시), Xum(워크스페이스별 토큰·비용), Orca(구독 한도만) | GUI에서 "이번 턴에 무엇이 들어갔나"를 여러 에이전트에 걸쳐 보여주는 곳 없음 |
| (d) 페이지가 작업 단위 | Augment Intent(살아 있는 스펙이 지휘), Nimbalyst(세션↔파일 양방향), Antigravity(산출물에 댓글), ChatGPT Work 모드 | 전부 실행은 worktree/스레드. 문서는 입력이거나 출력이지 컨테이너가 아니다 |
| (e) 결과를 페이지로 게시 | ChatGPT Sites(OpenAI 호스팅, 커스텀 도메인), Amp(스레드 공개 URL), Claude 아티팩트 | 오픈소스·BYO 구독 도구 중 게시하는 곳 없음 |

**포화된 곳**: worktree 대시보드, 에이전트 인식 터미널 멀티플렉서(Herdr, cmux, 그리고 우녕님의 tmux-agents가 바로 이 자리다), 칸반 카드→에이전트, 벤더 자체 병렬화, 이슈 트래커 구동 헤드리스(OpenAI Symphony).

**비어 있는 곳**: 위 다섯 축의 교집합. 특히 (b)+(c)+(d)는 어느 한 곳도 제대로 하지 않는다.

**시장이 실제로 아파하는 것**(HN·리뷰 반복 등장): 리뷰가 병목(타이핑 시간이 읽는 시간으로), worktree마다 DB·포트·의존성 재설치, 에이전트끼리 배운 것을 공유 못 함, 한도 소진에 대비책 없음. 이 넷은 각각 "페이지가 기록", "메모리 파일", "라우팅·대체", "사용량 표시"로 대응된다. **Madang의 차별점이 시장의 불만과 정확히 맞물린다.**

## 3. 문서·노트북·게시 지형: 방향 검증

비전을 7개 조각으로 나눠 50여 도구를 대조했다. V1 문서가 컨테이너, V2 HTML 템플릿+JSON 임베드, V3 터미널·프로세스 블록, V4 데이터 블록·바인딩, V5 내 도메인으로 게시, V6 메모리가 파일, V7 에이전트 대화가 문서 안.

**일곱 개를 다 하는 곳은 없다.** 가장 가까운 조합:
- Obsidian + Claudian(220만 다운로드) + Bases + Publish: V1·V5·V6·V7 강함. V2·V3 없음. 에이전트 대화는 사이드패널이지 페이지 안이 아니다.
- Observable Framework: V1·V2·V4·V5 강함. V6·V7 없음. 실행은 빌드 시점.

**이미 상품화된 조각** (여기서 경쟁하지 않는다):
- V5 게시: Notion Sites($8~10/도메인), Obsidian Publish, ChatGPT Sites, Manus, Lovable, Framer, Gamma. 호스팅으로는 차별화 불가. **무엇을 게시하느냐**(살아 있는 데이터, 실행 가능한 페이지, 소스를 내가 소유)로만 차별화된다.
- V3 마크다운 안의 실행 블록: Runme(펜스 속성 규약), Livebook `.livemd`, marimo, Jupyter. 실행은 풀렸고 "게시 뒤에도 살아 있는 페이지"는 안 풀렸다.
- V6 메모리 파일: Claude Code 자동 메모리, Obsidian 볼트를 메모리로 쓰는 커뮤니티(obsidian-second-brain 등). Codex는 파일이지만 편집을 권하지 않는다.
- V2 "AI는 JSON, 템플릿이 그림": 라이브러리로는 성숙(json-render 18k, Google A2UI, MCP Apps 표준, Vega-Lite). **문서 제품에 들어간 곳은 없다.**

**비어 있는 조각**:
- 에이전트 대화 기록이 페이지의 1급 블록(V7 문자 그대로). 아무도 안 한다.
- 게시 뒤에도 살아 있는 임베드(V2+V5). Claude 아티팩트·ChatGPT Sites는 되지만 마크다운 소스가 아니다.
- 마크다운 데이터 블록이 템플릿에 바인딩(V4+V2). Obsidian Bases만 마크다운 네이티브 데이터 뷰이고, HTML 템플릿 바인딩은 없다.
- 호출마다 세션을 버리고 페이지만 상태(V8). Codex·Claude Code만 세션을 일회용으로 보고, 문서 제품은 전부 채팅 세션을 유지한다.
- 작업과 같은 화면에서 메모리를 편집. Claude Code는 외부 편집기를 열고, Letta는 별도 ADE.

**판정: 문서 방향은 맞다.** 근거는 셋이다. (1) 비어 있는 조각이 정확히 Madang의 핵심이다. (2) Antigravity의 Artifacts, Augment Intent의 살아 있는 스펙, Nimbalyst의 세션↔파일, ChatGPT Work 모드까지, 시장이 "산출물을 문서로 보고 거기에 댓글을 단다"는 쪽으로 이미 움직이고 있다. (3) 문서 제품들의 반복되는 실패(Tome 20M 사용자·ARR 4M 미만 후 폐쇄와 데이터 삭제, Perplexity Pages 내보내기 불가, Claude 아티팩트 언퍼블리시 시 데이터 삭제, Notion 크레딧 소진 시 에이전트 정지)가 "디스크 위의 평범한 마크다운 + 정적 게시 경로"라는 우리 원칙의 가치를 보여준다.

**단, 조건이 있다.** "노트 앱"으로 읽히는 순간 Obsidian·Notion과 정면 경쟁이 된다. Madang의 페이지는 "무언가를 만들고 있는 작업"이어야 하고(비전 문서의 "되지 않을 것"), 첫 화면부터 실행 기록·라우터 줄·뷰 블록이 보여야 한다.

## 4. Orca에서 가져올 것 (구체)

우리 설계와 충돌하지 않는 것만 골랐다. 레이어·3열·페이지 단위는 유지한다.

| # | Orca 요소 | Madang 적용 | 단계 |
|---|---|---|---|
| 1 | **상태 글리프 어휘**: 스피너(작업 중), 호박색 물음표(사용자 필요), 초록 체크(완료), 빨간 점(막힘·실패), 회색 점(유휴). 탭과 사이드바 행에 같은 기호 | 페이지 카드와 실행 블록에 같은 어휘. Notebook Navigator 카드의 상태 칩을 이 기호로 | A2 |
| 2 | **읽지 않음은 배지가 아니라 굵게** | 페이지 카드 굵게. 정렬 "사용자 필요 → 완료 → 유휴" | A2 |

| 8 | **주석 트레이**: 여러 메모를 페이지 위에 남긴 뒤 "Send notes to" 한 번에 전송 | 편집 모드에서 요소 여러 개에 메모 → 요청 하나. **세션 없는 우리 모델에 정확히 맞는다**(메모가 곧 프롬프트) | A3 |
| 9 | **디프 주석**: 거터 +, 줄 고정 댓글, 편집 후에도 따라감, "Send to Agent"가 댓글 전부를 한 프롬프트로, Resolve | 코드 블록(Phase C)에 그대로 | C |

| 12 | **AI 작성 줄 표시(로컬 전용, 커밋 안 됨)** | 코드 블록 디프의 거터 표시. 저장소에는 절대 남기지 않는다(ADR D19와 양립) | C, 선택 |

| 15 | **Ghostty 설정·Warp 테마 가져오기** | 터미널 블록에 Ghostty 설정 가져오기 | C, 선택 |

**가져오지 않을 것**: IDE식 탭·분할 레이아웃(우리는 레이어), worktree가 단위인 것, 27종 에이전트 지원(우리는 Claude·Codex 둘에 집중하고 라우팅으로 차별화), 자체 Monaco 편집기(코드는 편집하지 않는다), 세션 재개(`--resume`, 우리는 세션을 버린다), 동면(세션이 없으니 불필요), 텔레메트리 기본 켜짐.

## 6. 가장 큰 전략적 갈림길: Obsidian

사실 관계:
- Notebook Navigator는 Obsidian 플러그인이다. 우녕님이 "이 화면 100%"라고 한 경험은 Obsidian 사용자의 경험이다.
- Claudian(Claude Code를 Obsidian 안에서)은 220만 다운로드다. "볼트를 에이전트 메모리로" 쓰는 프로젝트가 여럿이다.
- Obsidian은 V1·V5·V6·V7을 이미 갖고 있고, Bases로 V4 절반을, Publish로 V5를 갖고 있다. 없는 것은 V2(HTML 템플릿 바인딩), V3(터미널 블록), 라우팅, 호출별 입력 표시, 세션 없는 실행이다.

선택지:

| | 독립 KMP 앱 (현재) | Obsidian 플러그인 + Python core | 독립 앱 + Obsidian 호환 형식 (권장) |
|---|---|---|---|
| 도달 | 0에서 시작 | Claudian급 유통 채널, 익숙한 UI 그대로 | 0에서 시작하되 Obsidian 사용자가 앱 홈을 그대로 열 수 있음 |
| 언어 | Kotlin(사용자 선택) | TypeScript 강제 | Kotlin 유지 |
| 모바일 | KMP로 자체 | Obsidian 모바일은 플러그인 제약 큼 | KMP로 자체 |
| 샌드박스·WebView 제어 | 완전 | Electron 안이라 가능하나 플러그인 API 제약 | 완전 |
| 게시 | 자체(라이브 가능) | Obsidian Publish는 정적, 라이브 임베드 불가 | 자체 |
| 위험 | 사용자 확보 | Obsidian 정책·API 변경 종속, 노트 앱으로 읽힘 | 형식 호환 유지 비용 |

**권장: 독립 앱을 유지하되, 앱 홈의 파일 형식을 Obsidian 호환으로 잡는다.** 구체적으로 (1) 페이지·메모리·문서 블록은 위키링크(`[[...]]`)와 YAML 머리부를 Obsidian 규칙대로, (2) 데이터 뷰 정의는 Bases와 같은 YAML 구조, (3) 앱 홈 폴더를 Obsidian이 볼트로 열어도 깨지지 않게(`.obsidian/` 무시). 그러면 Obsidian 사용자에게 "볼트에 실행과 라우팅과 살아 있는 뷰를 더한 것"으로 설명할 수 있고, 나중에 얇은 Obsidian 플러그인(core에 붙는 클라이언트)을 내는 길도 열린다.

## 8. 위험 재평가

| 위험 | 판단 |
|---|---|
| 모델 회사가 같은 것을 만든다 | (b)(c)는 Claude Code가, (e)는 ChatGPT Sites가 **자기 모델 안에서** 이미 한다. 교차(a)는 서로 안 해 줄 것이다. Madang의 자리는 "둘 다 쓰는 사람의 중립 파일 소유 작업대"로 더 분명해졌다 |

| 리뷰 병목 | 페이지가 기록이라 리뷰가 "디프 읽기"에서 "결정·산출물 읽기"로 바뀐다. 이것이 사용자에게 설명할 첫 번째 가치 |

## 9. 한 줄 정리

Orca는 에이전트를 **돌리는** 곳이고, Madang은 에이전트가 한 일이 **남고 살아 있는** 곳이다. 돌리는 층은 Orca·Herdr·tmux-agents가 이미 잘하니 쓰고, 남고 살아 있는 층에 전부를 건다. 파일은 Obsidian이 열 수 있게, 뷰는 MCP Apps로 어디서나 그려지게, 게시는 버전과 데이터가 남게.
