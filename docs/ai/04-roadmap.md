# Madang: 로드맵

상태: 초안 (AI 작성, 미승인)
작성: 2026-09-24

각 Phase는 "사용자가 할 수 있게 되는 일" 하나로 정의한다. 완료 기준은 전부 사용자가 실제로 한 일이며, 못 넘기면 다음을 시작하지 않는다. 앞 Phase의 규칙을 뒤 Phase가 깨지 않는다.

## Phase A: 마당이 선다

**할 수 있게 되는 일.** 빌드된 앱을 띄우고, 3열 화면에서 대화하고, 대화가 정해진 흐름을 타고 에이전트가 매번 새 세션으로 이어가며, 페이지 안의 뷰를 확대해 조작하고 편집 모드에서 요소를 골라 대화로 고친다.

이 Phase는 원래 설계서의 0단계 + 1단계 + 2단계 일부(뷰 블록, 편집 모드)를 합친 것이다. 이유: 사용자가 "실제로 쓰는 도구"라고 느끼려면 화면 조작까지 있어야 한다.

### A0. 바탕 (화면 없음)
- 앱 홈 초기화, git 저장소.
- state.md 스키마와 검사기.
- 공통 작업 지시문.
- Runner: claude, codex 어댑터. 스트림 파싱.
- `madang run <page> --tool --model "요청"` CLI로 흐름 없이 단발 실행.
- `madang task/decide/artifact` CLI.
- 검증: 이력서 페이지를 세 번의 독립 호출(설계·작성·검토)로 진행. 각 입력 35K 이하, 세 커밋.

### A1. core 흐름
- LangGraph 그래프: classify(규칙+접두) → pick → assemble → run → validate → repair → judge → commit. 승격 루프, 교차 리뷰, ask_human.
- FastAPI + WebSocket. openapi.yaml.
- 미등록 파일 감지.
- 최근 삭제/복구.

### A2. 앱 뼈대
- KMP 프로젝트, desktop 타깃, Ktor 클라이언트 생성.
- 시작·온보딩·설정 화면. core 자동 실행.
- 레이어 0 3열. 블록: message, run, doc, data.
- 입력창과 preview-input 토큰 표시.
- 메모리 패널. 미등록 파일 띠. 사람 결정 카드.

### A3. 뷰와 편집
- 템플릿 규격, `madang.js`, 내장 템플릿 4개(table, decisions, tasks, resume). decisions·tasks 뷰는 state.md를 데이터로 페이지에 자동 생성.
- view 블록: 본문 축소 렌더, 레이어 1 실제 렌더.
- 레이어 1: 상단 탭, 연결 패널, 끌어다 놓기, 프리셋, 원본 보기, 승격.
- 보기/편집 토글, 레이어 2 요소 선택, 패널 직접 수정, 선택 요소만 담는 요청.

### A4. 패키징
- macOS dmg, Windows msi. core 바이너리 동봉.
- 권한 규칙 설치 마법사(사용자 승인).

**완료 기준.**
1. 사용자가 2주 동안 이력서 작업과 작은 저장소의 버그 하나를 이 앱만으로 끝낸다. 그 기간 터미널에서 `claude`/`codex`를 직접 연 횟수 0.
2. 호출당 입력 중앙값 35K 이하.
3. 이력서 템플릿 하나에 회사별 덮어쓰기 세 벌을 연결해 프리셋 전환으로 즉시 바뀐다. 회사 하나 추가에 AI 호출 1회, 입력 5K 이하.
4. 편집 모드에서 요소를 고르고 "이 섹션을 2단으로"가 해당 조각만 보내고 성공한다.

## Phase B: 문서가 산다

**할 수 있게 되는 일.** 템플릿을 사용자가 만들고 고친다. 스키마가 바뀌어도 데이터가 따라온다.

- 템플릿 만들기 흐름: 에이전트에게 "이런 화면" → 템플릿 폴더 생성 → 사용자 설치.
- 템플릿 버전과 스키마 변경 대응(변환 규칙 1회 생성, 일괄 적용, 누락 필드 목록).
- 편집 모드 드래그(요소 순서), 템플릿 고정 텍스트 수정 → 새 버전.
- 공간 `shared/` 데이터, 페이지 간 가져오기.
- 태그, 검색, 페이지 이동.

**완료 기준.** 사용자가 만든 템플릿 2개가 실제 페이지에서 쓰이고, 스키마 변경 1회를 데이터 손실 없이 넘긴다.

## Phase C: 실행이 산다

**할 수 있게 되는 일.** 페이지 안에서 서버를 띄우고, 응답을 화면으로 보고, 실제 사이트를 클릭해 고친다. 모바일에서 본다.

- 터미널 블록과 프로세스 관리자(생존, 재실행 정보, 시작 시 복구 제안).
- 사이트 블록(localhost). 코드 저장소와 연결된 사이트면 요소 선택 → 소스 경로.
- API 데이터 블록(주기, 인증 참조, 캐시).
- 코드 블록(diff, 전체 보기, 외부 편집기).
- 연결 추적 화면.
- Android·iOS 빌드. 데스크톱 core에 LAN 연결(토큰 인증). 모바일은 보기 + 입력창.

**완료 기준.** 백엔드 저장소에서 개발 서버를 터미널 블록으로 띄우고 `/health`를 5초마다 차트로 보며, 사이트 블록에서 요소를 골라 고친다. 앱 재시작 후 터미널 블록이 복구된다. 휴대폰에서 같은 페이지를 보고 메시지를 보낸다.

## Phase D: 판단이 자동이 된다

**할 수 있게 되는 일.** 모델을 고르지 않는다. 막히면 알아서 올라가고, 위험한 것은 앱이 막는다.

- 결정기 체인: 규칙 → 경량 모델(gpt-6-luna) → Jev(확보 시). 여섯 결정 지점 전부.
- 인계 테스트.
- 민감정보 필터(커밋 전), 완전 삭제.
- 사용량 화면(페이지·공간·기간, 구독 창 대비).

**완료 기준.** 2주간 사용자가 모델을 직접 지정한 호출 10% 이하. 승격 시 상위 모델 입력에 실패 로그 전문 없음. 키 형식 문자열 커밋 0회.

## Phase E: 밖으로 나간다

**할 수 있게 되는 일.** 페이지나 블록을 내 도메인 URL로 낸다. 블로그·랜딩·위키·대시보드.

- 게시 대상 선택, 블록 종류별 처리(정적 굳힘 / 서버 중계 / 제외), 게시용 프리셋.
- 도메인, 경로 규칙, 게시 이력·되돌리기.
- 공간을 "사이트"로 지정(목차, 태그).
- API 중계 서버 최소형.

**완료 기준.** 이력서가 `resume.<도메인>`으로, 프리셋별 URL로 게시된다. 공간 하나가 블로그로 게시되어 글 세 편이 묶인다. 게시본에 터미널·실행 기록·API 키 없음을 검사기가 확인한다.

## Phase F: 함께 쓴다

**할 수 있게 되는 일.** 남의 템플릿을 쓰고 내 것을 내놓는다. 구독 서비스로 제공한다.

- 템플릿 패키지·설치·버전 고정, 샌드박스(격리 origin, 네트워크 차단), 공개 저장소와 서랍.
- 서버 실행기(운영자 API 키, 크레딧). 로컬 실행기와 분리.
- 동기화(앱 홈 서버 호스팅), 릴레이.
- 요금: 로컬 코어 무료. 게시·중계·동기화·서버 실행 유료.

**완료 기준.** 외부 사용자가 만든 템플릿을 설치해 자기 데이터로 게시한다. 서버 실행기의 호출당 입력이 로컬과 같은 규모(30K 안팎).

## 순서에 대한 메모

- A는 크다. 그러나 A 안의 A0 → A1 → A2 → A3 → A4는 각각 하루~일주일 단위로 검증 가능하고, A0는 코드가 거의 없다.
- B와 C는 순서를 바꿔도 된다. 사용자가 이력서보다 백엔드 작업이 급하면 C를 먼저.
- D는 A~C를 실제로 써 본 데이터가 있어야 규칙을 잡을 수 있으므로 앞당기지 않는다.
- E와 F는 시장 검증 후.
