Claude와 Codex를 가리지 않고 쓰는 하나의 작업 공간. 대화가 곧 문서이고, 문서 안의 화면이 살아 있으며, 완성된 것은 그대로 배포된다. 이 문서는 "무엇을 만드는가"부터 객체 모델, 화면 모델, 단계별 범위까지를 모순 없이 한 줄로 잇는 것을 목표로 한다.

1. 무엇을 만드는가

한 문장으로: AI 코딩 에이전트와 함께 일하는 사람을 위한, 문서·화면·실행이 한곳에 있는 작업 공간.

지금은 네 가지 도구를 따로 씁니다. 에이전트에게 시키는 곳(Claude Code, Codex), 결과를 보는 곳(브라우저, 터미널), 결정과 맥락을 적는 곳(노션, 옵시디언), 완성물을 내보내는 곳(Vercel, GitHub Pages). 이 도구는 그 넷을 하나의 "페이지" 안에 넣습니다. 페이지 하나에 대화, 살아 있는 화면, 데이터, 실행 중인 프로세스가 같이 있고, 그 페이지를 그대로 배포할 수 있습니다.

이 도구가 되고 싶은 것

  • 중립 작업대. Claude와 Codex 중 무엇이 일했는지가 페이지에 남고, 다음 일을 누구에게 줄지는 규칙이 정한다.
  • 보이는 메모리. 에이전트가 매번 무엇을 읽는지가 파일로 있고, 사람이 그 파일을 고친다. 세션은 버리고 파일만 이어진다.
  • 살아 있는 문서. 문서 안의 화면은 데이터에 연결되어 있고, 데이터가 바뀌면 화면이 바뀐다. 표현은 템플릿이, 내용은 데이터가, 판단은 AI가 맡는다.
  • 배포되는 문서. 페이지 하나를 골라 내 도메인으로 내보낸다. 블로그, 랜딩 페이지, 위키, 대시보드가 같은 방식으로 만들어진다.

이 도구가 되지 않을 것

  • 코드 편집기가 아니다. 코드는 에이전트가 쓰고, 이 도구는 결과와 차이를 보여준다. 코드를 직접 고치고 싶으면 외부 편집기로 연다.
  • 모델 API 중계업이 아니다. 로컬에서는 사용자의 구독 CLI를, 서비스에서는 사용자별 크레딧을 쓴다. 가치는 모델 접근이 아니라 작업 방식에 있다.
  • 범용 노트 앱이 아니다. 모든 페이지는 "무언가를 만들고 있는 작업"이다. 메모만 하는 용도는 다른 도구가 낫다.

2. 설계 원칙 7가지

이후의 모든 결정은 이 일곱 개로 환원된다. 새 기능을 넣을 때 이 중 하나라도 어기면 넣지 않는다.

  1. 페이지 폴더가 진실이다. 화면에 보이는 모든 것은 디스크의 파일을 그린 결과다. 화면에만 있고 파일에 없는 상태는 없다. 그래서 삭제는 파일 삭제이고, 복구는 git이다.
  2. 모든 것은 블록이다. 대화 메시지, 화면, 데이터, 터미널, 코드 파일이 전부 같은 크기의 단위이며, 같은 방식으로 확대되고 연결되고 삭제된다. 예외 블록을 만들지 않는다.
  3. 트리는 하나다. 왼쪽 탐색은 공간과 페이지의 트리 하나뿐이다. 코드 저장소의 파일 트리는 탐색이 아니라 블록 안에서만 보인다.
  4. 입력창은 항상 "지금 보고 있는 것"에게 말한다. 페이지를 보면 페이지에게, 블록을 확대하면 블록에게, 요소를 선택하면 요소에게. 입력창은 하나이고 대상만 바뀐다.
  5. AI는 데이터를 쓰고, 표현은 템플릿이 한다. AI가 HTML을 매번 만들지 않는다. 형식이 정해진 데이터만 쓰고, 앱이 그린다.
  6. 세션은 버리고 파일은 잇는다. 에이전트 호출은 매번 새 세션이며, 이어지는 것은 페이지 폴더의 문서뿐이다. 매 호출 입력의 크기는 사람이 눈으로 볼 수 있다.
  7. 부작용은 앱 명령을 통해서만. 커밋, 푸시, 삭제, 승격, 배포는 에이전트가 직접 하지 않고 app 명령으로 요청한다. 위험 판단은 모델이 아니라 앱 코드에 있다.

3. 객체 모델

이름을 먼저 고정한다. 화면, 파일, 코드에서 같은 이름을 쓴다.

객체정의디스크화면
Space (공간)페이지의 묶음. 선택적으로 코드 저장소 하나와 연결된다. 루트 공간은 항상 있다.spaces/<name>/ + space.md왼쪽 트리의 상위 노드
Page (페이지)하나의 작업이자 대화이자 문서. 모든 활동은 페이지 안에서 일어난다. "채팅"과 "문서"는 같은 것의 두 이름이다.pages/<id>/ 폴더 전체트리의 하위 노드, 가운데 본문
Block (블록)페이지 안의 단위. 종류가 있다: 메시지, 문서, 뷰, 데이터, 코드, 터미널, 사이트, 실행 기록.페이지 폴더 안의 파일 하나 (메시지는 log.md의 한 항목)본문에 세로로 쌓인 카드
Template (템플릿)뷰 블록이 쓰는 표현. 슬롯(받는 데이터 형식)과 렌더링을 가진다. 내장 또는 사용자 제작.templates/<name>/ (page.html, schema.json, sample.json)뷰 블록의 "템플릿" 표시, 템플릿 서랍
Data (데이터)템플릿 슬롯에 들어가는 값. 파일이거나, API 주소이거나, 다른 블록의 출력이다.*.json, *.csv 또는 source.yaml(API)데이터 블록, 연결 패널의 항목
Binding (연결)"이 뷰의 이 슬롯에 이 데이터"라는 한 줄. 여러 연결을 이름 붙여 저장한 것이 Preset이다.뷰 블록 파일의 머리부 bindings:연결 패널의 선, 프리셋 선택
Memory (메모리)에이전트가 매 호출 읽는 문서. 세 층: 루트, 공간, 페이지.root.md, space.md, state.md메모리 패널
Run (실행)에이전트 호출 한 번. 어느 도구, 어느 모델, 무엇을 읽었고, 무엇을 바꿨는가.runs/<n>.json본문의 실행 기록 블록, 실행 패널
Process (프로세스)터미널 블록 뒤에서 도는 실제 셸. 페이지를 닫아도 산다. 죽으면 재실행 정보만 남는다.procs/<id>.yaml + 출력 로그터미널 블록의 상태 표시

페이지 폴더

pages/2026-09-24-resume/
├ page.md          제목, 종류, 상태, 만든 날짜 (머리부) + 사람이 쓰는 개요
├ state.md         에이전트 메모리 (머리부: 결정·작업·산출물 목록 / 본문: 서술)
├ log.md           대화 로그. 메시지 블록의 원본. 한 항목 = 한 블록
├ blocks/
│  ├ 01-resume.view.md      뷰 블록: template, bindings 머리부
│  ├ 02-base.json           데이터 블록
│  ├ 03-pearlabyss.json     데이터 블록
│  ├ 04-jobpost.source.yaml 데이터 블록 (API)
│  ├ 05-dev.term.yaml       터미널 블록 (명령, cwd, 프로세스 id)
│  └ 06-preview.site.yaml   사이트 블록 (url)
├ runs/            실행 기록 (앱이 씀)
└ scratch/         임시물. git 제외, 실행 끝나면 정리

불변조건 1. 본문에 보이는 블록의 순서는 page.md의 blocks: 목록 순서다. 블록을 옮기면 그 목록이 바뀐다. 파일명 접두 번호는 사람이 폴더를 열었을 때의 편의일 뿐 진실이 아니다.

불변조건 2. 블록은 자신이 속한 페이지 폴더 안의 파일만 참조한다. 다른 페이지의 데이터를 쓰고 싶으면 "가져오기"로 복사하거나, 공간 수준 shared/로 승격해 둘 다 그것을 본다. 숨은 참조를 만들지 않는다.

공간과 코드 저장소

공간은 코드 저장소 경로 하나를 가질 수 있다. 에이전트는 그 경로에서 실행된다. 코드 저장소 안에 이 도구의 파일은 docs/로 승격된 문서 외에는 아무것도 생기지 않는다. 앱의 모든 파일은 앱 홈(비공개 git 저장소) 안에 있다.

4. 화면 모델과 충돌 해소

기존 도구들의 "왼쪽 채팅, 오른쪽 브라우저" 분할이 불편했던 이유는 두 화면이 서로를 모르기 때문이다. 이 도구는 분할 대신 레이어를 쓴다. 항상 한 가지만 크게 보이고, 나머지는 그 주변에 붙는다.

레이어 0: 페이지

  • 왼쪽은 공간과 페이지의 트리 하나뿐이다. 파일 트리는 없다.
  • 가운데 본문은 블록이 시간순으로 쌓인 흐름이다. 대화와 문서가 같은 흐름 안에 있다.
  • 뷰 블록은 코드 블록처럼 본문에 임베드되며, 축소된 실제 렌더링을 보여준다.
  • 입력창은 본문 아래 하나. 대상은 "페이지".

레이어 1: 블록 초점

블록을 클릭하면 그 블록이 본문 위로 떠오른다. 전체 화면이 아니라 여백이 남는 크기다. 뒤의 페이지는 흐려지지만 사라지지 않아 "어디에 있는지"를 잃지 않는다.

  • 상단 탭은 이 페이지의 다른 확대 가능한 블록이다. 말씀하신 "왼쪽 상단에 만들어진 브라우저들"이 여기다. 페이지를 벗어나지 않고 화면 사이를 오간다.
  • 오른쪽 연결 패널은 이 블록의 슬롯과 거기 연결된 데이터다. 빈 슬롯(○)에 페이지의 데이터 블록을 끌어다 놓으면 연결된다. 슬롯에 마우스를 올리면 왼쪽 트리 대신 페이지의 데이터 블록 목록이 필터링되어 뜬다(맞는 형식만 밝게).
  • 입력창은 같은 자리에 있되 대상이 "이력서 뷰"로 바뀐다. 여기서 보낸 말은 이 블록의 파일과 연결 데이터만 에이전트에게 간다.
  • Esc 또는 바깥 클릭이면 레이어 0으로 돌아간다.

레이어 2: 요소 선택

레이어 1에서 렌더링된 화면 안의 요소를 클릭하면, 연결 패널에서 그 요소가 어느 데이터에서 왔는지(base.json > work[1].company)가 강조되고, 입력창 앞에 선택 칩이 붙는다.

│ [경력 2번 회사명]  펄어비스 경력을 맨 위로 올려줘         [보내기] │
  • 글자와 스타일 값은 연결 패널에서 직접 고친다. AI를 부르지 않는다.
  • 구조 변경은 입력창으로 말한다. 에이전트에게는 선택한 요소의 HTML 조각 + 데이터 경로 + 요청만 간다.
  • Ctrl+클릭으로 여러 요소를 고르면 칩이 여러 개 붙는다.

충돌 해소 목록

충돌해소
채팅 트리와 파일 트리가 둘 다 왼쪽에 필요하다파일 트리를 없앤다. 코드 저장소는 "코드 블록"으로만 본다. 코드 블록은 특정 파일 하나를 열고, 마지막 실행 이후의 diff를 기본으로 보여준다. 저장소 전체를 훑고 싶으면 "외부 편집기에서 열기" 버튼. 이 도구는 코드를 편집하는 곳이 아니라는 원칙 1과 일치한다.
화면을 확대하면 채팅이 사라져 맥락을 잃는다전체 화면 대신 레이어. 뒤의 페이지가 흐리게 남고, 입력창은 같은 자리에서 대상만 바뀐다.
만들어진 화면이 여러 개면 어디서 고르나레이어 1의 상단 탭. 페이지 밖의 화면은 트리에서 그 페이지로 가야 보인다. 화면은 항상 페이지에 속한다.
파일을 어디에 끌어다 놓나레이어 1의 연결 패널 빈 슬롯. 레이어 0에서는 끌어다 놓기가 없다(한 동작 한 기능).
삭제하면 진짜 삭제되나된다. 블록 삭제 = 파일 삭제, 페이지 삭제 = 폴더 삭제. 앱 저장소가 git이므로 "최근 삭제" 목록에서 되살릴 수 있다. 되살리기는 git revert다.
코드는 어떻게 보여주나코드 블록. 파일 경로, 마지막 실행의 diff, 전체 보기 토글. 편집은 하지 않는다(1단계). 에이전트에게 "이 파일 이렇게 고쳐"는 레이어 1에서 그 블록에게 말한다.
메시지도 블록인가그렇다. 메시지를 클릭하면 레이어 1에 그 메시지와 그 직후 실행 기록이 뜨고, 연결 패널에는 그 실행이 읽은 파일 목록이 보인다. "이때 무엇을 읽고 무엇을 바꿨나"가 보인다.
대화가 길어지면 본문이 너무 길다본문은 시간순이지만 "접기"가 있다. 실행 기록과 오래된 메시지는 자동으로 접히고, 뷰·데이터·터미널 블록은 접히지 않는다. 문서로서의 페이지는 접히지 않은 블록들이다.

5. 한 동작 = 한 기능 표

사용자가 배워야 하는 동작은 아래가 전부다. 새 기능은 이 표에 새 줄을 추가하지 않고 기존 줄에 붙어야 한다.

동작레이어 0 (페이지)레이어 1 (블록 초점)레이어 2 (요소 선택)
클릭블록 → 초점(레이어 1)화면 안 요소 → 선택(레이어 2). 상단 탭 → 다른 블록으로 초점 이동다른 요소 → 선택 교체
Ctrl+클릭블록 여러 개 선택 (이동·삭제용)요소 여러 개 선택선택 추가
끌어다 놓기블록 순서 바꾸기데이터 블록 → 빈 슬롯 = 연결없음
입력 후 보내기페이지에게 (라우터가 종류·모델 결정)이 블록에게 (블록 종류가 종류를 결정)선택 요소에게 (항상 small 종류)
Esc선택 해제레이어 0으로선택 해제 (레이어 1 유지)
Delete선택 블록 삭제 (파일 삭제, 되살리기 가능)이 블록 삭제 후 레이어 0없음 (요소 삭제는 말로)
연결 패널에서 값 수정없음데이터/스타일 값 직접 수정 → 파일 저장 → 즉시 다시 그림선택 요소의 값만 표시·수정
"승격"없음이 블록의 파일을 코드 저장소 docs/로 복사·커밋없음
"게시"페이지 전체를 URL로 (5단계)이 블록만 URL로 (5단계)없음

규칙. 같은 동작이 레이어마다 다른 일을 하되, 각 레이어 안에서는 한 가지 일만 한다. "클릭"이 어떤 때는 열고 어떤 때는 선택하는 상황은 레이어가 다를 때만 허용된다.

6. 에이전트 계약

에이전트(Claude Code, Codex)는 이 도구를 모른다. 그래서 도구가 에이전트에게 주는 것과 받는 것을 고정한다.

주는 것 (매 호출, 새 세션)

[도구 기본 시스템 프롬프트 + 툴 정의]   에이전트 것, 약 25K, 캐시됨
[root.md]                              사용자 규칙, 100~300 토큰
[space.md]                             이 공간·저장소 규칙, 1~2K
[state.md]                             이 페이지의 메모리, 2K 상한
[공통 작업 지시문]                       아래 계약, 약 500
[대상 블록의 파일 + 연결 데이터]          레이어 1·2일 때만
[이번 요청]

합계는 페이지가 아무리 길어도 30K 안팎이다. 이 합계가 입력창 옆에 항상 표시된다.

받는 것

  • state.md 갱신. 머리부의 status, decisions, tasks, artifacts는 형식 검사를 통과해야 저장된다.
  • 블록 파일의 생성·수정. 새 파일은 반드시 artifacts:에 등록한다. 등록 없이 코드 저장소에 생긴 파일은 앱이 "정체불명"으로 걸어 사용자에게 보인다.
  • 부작용 요청은 app 명령으로만: app promote, app commit, app push, app decide, app task. 날것의 git push, rm -rf는 권한 규칙으로 막는다.

공통 작업 지시문 (요지)

너는 페이지 하나의 한 단계만 수행한다.
1. state.md를 읽고 "다음 할 일"을 수행한다.
2. 새 문서는 blocks/에 만들고 state.md의 artifacts에 등록한다.
3. 화면이 필요하면 HTML을 쓰지 말고 view 블록(template + data)을 쓴다.
4. 같은 검증이 2회 연속 실패하면 status: blocked, "막힌 점" 5줄, 즉시 종료.
5. 구현이 끝나면 status: review.
6. 커밋·푸시·삭제·승격은 app 명령으로만 요청한다.
7. state.md는 2,000토큰을 넘기지 않는다. 넘으면 로그를 요약한다.

라우팅 표 (초기값, 설정 파일)

designclaude opus-5-5 · highclaude fable-5-1 · high사람

종류 판정은 결정기(Decider) 인터페이스를 통한다. 입력은 요청과 선택지, 출력은 선택과 확신도. 구현체는 규칙 → 경량 모델 → Jev 순으로 교체 가능하며, 확신도가 기준 미만이면 다음 구현체로 넘긴다. 레이어 1·2에서 보낸 요청은 블록 종류가 곧 작업 종류이므로 결정기를 거치지 않는다.

7. 단계별 범위

각 단계는 "사용자가 할 수 있게 되는 일" 하나로 정의한다. 단계 안의 항목은 그 일에 꼭 필요한 것만이며, 다음 단계의 것을 미리 넣지 않는다. 각 단계 끝의 완료 기준을 통과해야 다음으로 간다.

0단계. 바탕: 파일과 계약

화면 없이, 파일과 CLI만으로 "세션을 버리고 문서로 잇는 것"이 되는지 확인한다.

만드는 것

  • 앱 홈 폴더 구조와 초기화 명령. 앱 홈은 git 저장소로 초기화된다.
  • state.md 양식(머리부 스키마 포함)과 검사기. 형식 오류, 상한 초과, 존재하지 않는 경로 참조를 잡는다.
  • 공통 작업 지시문 파일.
  • 실행기 명령 ws run <page> --tool claude|codex --model … "요청". 입력을 조립해 CLI를 새 세션으로 호출하고, 끝나면 검사기를 돌리고, runs/에 기록하고, 앱 저장소에 커밋한다.
  • app 명령의 최소 집합: app task, app decide, app commit. 에이전트 권한 규칙에 app * 허용 추가.

객체

Space(루트만), Page, Memory, Run. 블록은 아직 파일로만 존재한다.

하지 않는 것

화면, 라우터, 템플릿, 프로세스. 모델 선택은 사람이 명령줄에서 한다.

완료 기준. 이력서 페이지 하나를 만들고, Claude로 설계 → Codex로 데이터 작성 → Claude로 검토를 세 번의 독립 호출로 진행했을 때, 각 호출이 이전 호출의 세션 없이 state.md만으로 이어지고, 세 호출의 입력 합계가 각각 35K 이하이며, 결과 파일이 앱 저장소에 세 커밋으로 남는다.

1단계. 쐐기: 페이지와 세 블록

사람이 매일 열어 두는 화면이 생긴다. 페이지 안에서 대화하고, 메모리를 고치고, 뷰 하나를 본다. 이 단계가 앞서 말한 "최소 범위"다.

만드는 것

  • 레이어 0 전체: 왼쪽 공간 트리, 가운데 블록 흐름, 아래 입력창. 공간 생성·삭제, 페이지 생성·삭제. 공간에 코드 저장소 경로 연결.
  • 블록 세 종류: 메시지(사용자·에이전트·라우터 줄), 문서(md, mermaid 렌더링 포함), 데이터(json 표 형태 보기·편집).
  • 레이어 1의 최소형: 블록 클릭 시 확대, 오른쪽 패널에는 "이 블록의 파일 원본"만. 연결 패널은 아직 없다. 입력창 대상 전환은 된다.
  • 메모리 패널: root.md, space.md, state.md를 보고 고친다. 입력창 옆에 "다음 호출 입력 합계" 표시.
  • 라우터 1차: 키워드 규칙과 사용자 접두(design:)만. 규칙에 안 걸리면 build. 승격 루프(blocked → 상위)는 넣는다. 교차 리뷰는 넣는다.
  • 실행 기록 블록: 도구, 모델, 입력·출력 토큰, 바뀐 파일 목록, 소요 시간.
  • 정체불명 파일 감지: 실행 전후 git status 비교, 미등록 파일을 페이지 상단에 표시. 처리는 "산출물로 / 유지 / 삭제" 세 버튼.
  • 삭제와 되살리기: 블록·페이지 삭제, "최근 삭제" 목록에서 복구.

객체

Block(메시지·문서·데이터), Run이 화면에 나타난다. 나머지는 0단계와 같다.

하지 않는 것

템플릿과 뷰 블록, 연결 패널, 끌어다 놓기, 요소 선택, 터미널·사이트·코드 블록, 경량 모델 결정기, 게시.

완료 기준. 사용자가 2주 동안 실제 작업(이력서 데이터 정리, 작은 저장소의 버그 하나)을 이 화면만으로 끝낸다. 그 기간 동안 터미널에서 직접 claude나 codex를 연 횟수가 0이다. 각 페이지의 호출당 입력 중앙값이 35K 이하다.

2단계. 살아 있는 뷰: 템플릿과 연결

"디자인은 한 번, 데이터는 여러 벌"이 된다. 끌어다 놓아 연결하고, 화면 요소를 골라 말한다.

만드는 것

  • 템플릿 규격: page.html(data-bind 표시), schema.json(슬롯과 형식), sample.json, theme.json. 내장 템플릿 4개: 표(compare), 카드 보드(decisions), 간트(tasks), 이력서.
  • 뷰 블록: 템플릿 + 연결. 본문에서는 축소 렌더링, 레이어 1에서는 실제 크기.
  • 레이어 1 완성: 상단 탭(페이지의 확대 가능 블록), 오른쪽 연결 패널(슬롯, 연결된 데이터, 빈 슬롯). 슬롯에 마우스를 올리면 페이지의 데이터 블록이 형식 일치 여부로 필터링되어 표시된다. 끌어다 놓기 = 연결.
  • 연결 패널에서 값 직접 수정 → 파일 저장 → 즉시 다시 그림. 이 경로에 AI는 없다.
  • 프리셋: 현재 연결 조합을 이름 붙여 저장·전환. 프리셋은 뷰 블록 머리부에 저장된다.
  • 레이어 2: 요소 클릭으로 데이터 경로 강조, 선택 칩, 선택 요소만 담아 보내는 요청(small 종류 고정).
  • 스키마 변경 대응: 템플릿의 schema가 바뀌면 연결된 모든 데이터를 검사해 "필드 없음" 목록을 띄우고, 변환 규칙을 에이전트에게 한 번 만들게 해 일괄 적용.
  • 결정 보드와 간트는 state.md 머리부(decisions, tasks)를 데이터로 쓰는 뷰 블록으로 페이지에 자동 추가된다. 별도 기능이 아니라 템플릿 4개 중 둘이다.
  • AI 지시문에 "view 블록을 쓰고 HTML을 쓰지 말 것"과 내장 템플릿 목록(약 500 토큰) 추가.

객체

Template, Data(파일), Binding, Preset. 뷰 블록.

하지 않는 것

API 데이터, 프로세스, 사용자 제작 템플릿의 공유, 게시.

완료 기준. 이력서 템플릿 하나에 회사별 덮어쓰기 데이터 세 벌을 연결해 프리셋 전환으로 세 이력서가 즉시 바뀐다. 회사 하나 추가에 드는 AI 호출이 1회, 입력 5K 이하다. 요소 선택 후 "이 섹션을 2단으로" 요청이 전체 페이지가 아닌 해당 조각만 보내고 성공한다.

3단계. 살아 있는 실행: 프로세스와 실시간 데이터

페이지 안에서 서버를 띄우고, 그 서버의 응답을 화면으로 보고, 실제 사이트를 클릭한다.

만드는 것

  • 터미널 블록: 명령과 cwd를 가진다. 뒤에서 실제 프로세스가 돌고 출력이 파일로 쌓인다. 페이지를 닫아도 산다. 프로세스가 죽으면 "종료됨 · 다시 실행"이 뜬다. 앱 시작 시 "지난 프로세스 다시 켤까요"를 한 번 묻는다.
  • 사이트 블록: URL을 가진다. 레이어 1에서 실제 페이지가 보이고 클릭된다. 같은 공간의 코드 저장소에서 띄운 localhost면 레이어 2의 요소 선택이 동작한다(연결 패널에는 데이터 경로 대신 소스 파일 경로가 뜬다).
  • 데이터 블록의 API 형태: URL, 주기, 인증 헤더 참조(값은 앱 비밀 저장소에). 주기마다 받아 연결된 뷰를 다시 그린다.
  • 코드 블록: 코드 저장소의 파일 하나. 마지막 실행의 diff 기본 표시, 전체 보기 토글, "외부 편집기에서 열기". 편집 없음.
  • 에이전트에게 터미널 출력을 넘길 때는 전체가 아니라 마지막 N줄 또는 오류 부근만 넘긴다. N은 블록 설정.
  • 연결 추적 화면: 블록을 골라 "이 값은 어디서 왔나"를 화살표로 거슬러 보여준다. 데이터 → 변환 → 뷰의 사슬이 이 단계부터 길어지므로 여기서 넣는다.

객체

Process. Data(API). 코드·터미널·사이트 블록.

하지 않는 것

코드 편집, 원격 프로세스, 게시.

완료 기준. 백엔드 저장소 하나에서 개발 서버를 터미널 블록으로 띄우고, /health 응답을 5초마다 받아 차트 뷰로 보고, 사이트 블록에서 로그인 화면을 클릭해 요소를 고른 뒤 "이 버튼 색 바꿔"를 보내 에이전트가 해당 소스 파일만 고친다. 앱을 껐다 켜도 터미널 블록이 "종료됨 · 다시 실행"으로 복구된다.

4단계. 판단의 자동화: 결정기와 안전장치

사람이 모델을 고르지 않는다. 막히면 알아서 올라가고, 위험한 것은 앱이 막는다.

만드는 것

  • 결정기 인터페이스와 구현체 세 개: 규칙, 경량 모델(gpt-6-luna), Jev(early access 확보 시). 확신도 기준과 폴백 순서는 설정.
  • 결정 지점 여섯 곳을 결정기로 통일: 요청 종류, 도구·모델, 막힘 판정, state.md 인계 충분성, 새 파일 분류, 리뷰 통과.
  • 인계 테스트: 실행 후 갱신된 state.md만 경량 모델에 주고 "다음에 무엇을 어디서 시작하나"를 묻는다. 모호하면 작성 세션에 보강 요구.
  • 민감정보 필터: 커밋 직전 변경 파일을 검사(키·토큰 패턴, 높은 엔트로피 문자열). 걸리면 커밋을 멈추고 위치를 보여준다. 가림 / 무시 / 파일 제외.
  • 완전 삭제: 일반 삭제(git 히스토리 보존)와 구분되는 "히스토리에서도 제거".
  • 사용량 화면: 페이지·공간·기간별 호출 수, 토큰, 도구 비율. 구독 한도 창(5시간·주간) 대비 표시.
  • 사람 개입 지점: 결정기 확신이 낮거나 최상위에서도 막히면 흐름이 멈추고 페이지 상단에 선택지가 뜬다. 고르면 그 지점부터 재개(LangGraph interrupt).

하지 않는 것

게시, 공유, 서비스.

완료 기준. 2주 동안 사용자가 모델을 직접 지정한 호출이 전체의 10% 이하. 승격이 일어난 페이지에서 상위 모델이 받은 입력에 실패 로그 전문이 포함되지 않는다. 키 형식 문자열이 든 파일이 커밋된 적이 0회.

5단계. 밖으로: 게시

페이지나 블록 하나를 내 도메인의 URL로 내보낸다. 블로그, 랜딩 페이지, 위키, 대시보드가 여기서 나온다.

만드는 것

  • 게시 대상 선택: 페이지 전체 또는 블록 하나. 게시 시 블록 종류별 처리 규칙: 문서·뷰·데이터(파일)는 정적으로 굳힘, 데이터(API)는 서버 중계, 메시지·실행 기록·터미널·코드는 제외(기본값, 문서·실행 기록은 켤 수 있음).
  • 게시 대상의 "게시용 프리셋": 같은 뷰를 내부용과 외부용 연결로 나눠 둔다.
  • 도메인 연결, 경로 규칙(/resume, /blog/<page>), 게시 이력과 되돌리기.
  • 공간 하나를 "사이트"로 지정하면 그 안의 게시된 페이지들이 목차·태그로 묶인다. 블로그와 위키는 이 설정의 두 모양이다.
  • API 중계 서버(최소형): 게시된 페이지의 API 데이터 블록을 대신 호출. 키는 서버에만. 주기와 캐시.

하지 않는 것

댓글·협업, 다중 사용자, 템플릿 마켓.

완료 기준. 이력서 페이지가 resume.<도메인>으로 게시되고, 프리셋별 URL이 따로 나온다. 공간 하나가 블로그로 게시되어 글 세 편이 목차로 묶인다. 게시본에 터미널·실행 기록·API 키가 포함되지 않았음을 검사기가 확인한다.

6단계. 함께: 템플릿 생태계와 서비스

남이 만든 템플릿을 쓰고, 내 템플릿을 내놓고, 구독 서비스로 제공한다.

만드는 것

  • 템플릿 패키지 규격(버전, 스키마, 샘플, 미리보기)과 설치·업데이트. 페이지는 템플릿 버전을 고정 참조한다.
  • 샌드박스: 외부 템플릿과 코드 셀은 격리된 iframe에서 실행. 네트워크·파일 접근 없음. 전달받은 JSON만 본다.
  • 템플릿 공개 저장소와 앱 안의 서랍(검색, 미리보기, 설치).
  • 서비스 실행기: 로컬 실행기(사용자 구독 CLI)와 나란히, 서버 실행기(운영자 API 키, 사용자별 크레딧). 앱 코드는 같고 실행기만 다르다.
  • 동기화: 앱 저장소를 서버가 호스팅. 여러 기기에서 같은 공간.
  • 요금: 로컬 코어 무료. 게시·중계·동기화·서버 실행이 유료. 크레딧 상한과 사용량 알림.
완료 기준. 외부 사용자가 만든 템플릿을 설치해 자기 데이터를 연결하고 게시까지 마친다. 서버 실행기로 진행한 페이지의 호출당 원가가 로컬 실행기와 같은 입력 규모(30K 안팎)를 유지한다.

8. 위험과 대응

위험대응
모델 회사가 같은 기능을 자기 앱에 넣는다이 도구의 위치는 "둘 다 쓰는 사람의 중립 작업대 + 보이는 메모리 + 배포". 어느 한 회사도 다른 회사 모델로 보내주지 않고, 메모리를 파일로 열어 주지 않는다. 그 교차점을 벗어나는 기능은 후순위.
state.md 품질이 낮아 다음 세션이 헤맨다사실(변경 파일, 결과)은 앱이 쓰고 판단만 에이전트가 쓴다. 검사기와 인계 테스트. 좋은 예시 하나를 지시문에.
블록 종류가 늘며 예외가 생긴다원칙 2. 새 블록은 "확대·연결·삭제"가 기존 방식 그대로 동작해야 추가된다. 그러지 못하면 블록이 아니라 다른 것이다.
연결이 복잡해져 원인을 못 찾는다3단계의 연결 추적 화면. 연결은 항상 페이지 안(불변조건 2).
범위가 커져 완성되지 않는다각 단계의 완료 기준은 "사용자가 실제로 한 일"이다. 기준을 못 넘기면 다음 단계를 시작하지 않는다. 1단계는 사용자 본인이 2주 쓰는 것으로 검증한다.
구독 CLI를 서비스에 쓰는 약관 문제서비스 실행기는 API 키만. 로컬 실행기는 사용자 본인 구독만. 코드에서 둘을 섞지 않는다.
정액 요금 vs 토큰 원가호출당 입력 상한(원칙 6), 경량 모델 우선 라우팅, 결정기. 크레딧제로 상한.

바로 시작할 것

0단계는 코드가 거의 없다. 앱 홈 폴더 구조, state.md 양식과 검사기, 공통 지시문, ws run 한 명령. 이 넷으로 이력서 페이지를 세 번의 독립 호출로 진행해 보면 이 설계의 핵심 가정("세션 없이 문서로 잇기")이 맞는지 하루 안에 확인된다.

가정: 로컬 우선, 앱 홈은 비공개 git 저장소, 에이전트는 사용자 구독 CLI. 이름(Space, Page, Block 등)은 임시이며 바꿔도 구조는 같다.
