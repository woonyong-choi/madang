2. Claude 모델 설명

Fable 5.1 최상위

포지션
Mythos 5.1과 같은 모델에 안전장치를 추가한 공개 버전. "Opus 5.5를 높은 effort로 돌려도 부족할 때" 쓰라는 것이 공식 가이드입니다.
사고 방식
Adaptive thinking 상시 켜짐(끌 수 없음). 기본 effort high, 최대 max.
토큰 특성
입력 $10, 출력 $50로 Opus 5.5의 2.5배. 대신 캐시 읽기가 기본가의 2.5%($0.25)로 모든 모델 중 가장 저렴한 비율입니다. 캐시 최소 길이 512토큰.
구독 조건
Max·Premium 시트는 주간 한도의 50%까지 Fable 사용 가능. Pro·Standard 시트는 플랜 한도에 포함되지 않아 별도 사용 크레딧이 필요합니다.
주의
강제 tool_choice 불가. 이전 턴 편집 시 thinking 블록이 무효화됩니다. 다른 모델이 Fable의 thinking 블록을 읽을 수 없어 대화 중 모델 전환 시 재처리가 생깁니다.

Opus 5.5 주력

포지션
2026-09-22 출시. Anthropic 공식 "대부분의 워크로드는 여기서 시작". Claude Code의 default 별칭이 이 모델을 가리킵니다.
사고 방식
Adaptive 상시 켜짐. 기본 effort가 medium으로 유일하게 낮게 잡혀 있어, 그대로 쓰면 이전 Opus보다 출력 토큰이 적습니다.
토큰 특성
입력 $4, 출력 $20(Opus 5보다 20% 인하). 캐시 읽기 5%($0.20). 서버 측 컨텍스트 관리가 thinking 블록을 절대 무효화하지 않아 장기 세션의 캐시 효율이 높습니다. Fast mode 시 2배 요금($8/$40).
적합 작업
다중 파일 기능 구현, 장시간 자율 에이전트, 설계 판단이 필요한 리팩터링.

포지션

적합 작업
일반 코딩, 코드 리뷰, 테스트 작성, 서브에이전트 팀원 역할.

포지션

구세대 참고

3. Codex(OpenAI GPT-6) 모델 설명

2026-09-22 GPT-6 Sol과 Luna가 출시되면서 Codex 권장 모델이 3종으로 정리됐습니다. GPT-5.5는 2026-10-14에 ChatGPT 로그인 Codex에서 은퇴하고 API에만 남습니다. GPT-5.4 / 5.4-mini는 이미 8월 31일에 은퇴했고, gpt-5.3-codex는 API 전용($1.75/$14)으로만 남아 있습니다.

GPT-6 Astra 최상위

추론 설정

포지션
Codex 기본 권장 모델(codex --model gpt-6-sol). 복잡한 코드 변경, 딥 리서치, 문서 작업.
추론 설정
effort none / low / medium(기본) / high / xhigh / max / ultra. API 가격이 GPT-5.6 Sol($4/$20)의 절반으로 영구 인하.

입력 $2, 출력 $10, 캐시 읽기 $0.20. Claude Sonnet 5와 정확히 같은 단가. 272K 초과 시 $4/$15. Plus 기준 5시간당 15~150개 메시지.

GPT-6 Luna 경량

포지션
"명확하고 반복 가능한 작업" 전용. 추출·분류·변환·구조화 요약·집중 코딩. Free·Go 플랜의 Codex 기본 모델.
추론 설정
effort none ~ max(Ultra 없음). Codex 권장 시작점은 high. 경량 모델이라 effort를 올려도 절대 토큰량이 작습니다.
토큰 특성
입력 $0.10, 출력 $0.50. Sol의 1/20. Claude Haiku 4.5보다 10배 저렴하면서 컨텍스트는 1.05M. Plus 기준 5시간당 350~3,000개 메시지.

Codex 전용 개념

  • Power 프리셋: 앱 슬라이더는 Luna High → Sol Light → Sol Medium → Astra Light → Astra Medium → Astra Extra High 순. "Faster" 방향이 곧 토큰 절감입니다.
  • Max: 단일 작업에 추론 시간을 더 줌. Ultra: 서브에이전트를 병렬로 띄움. 공식 문서도 "대부분 작업은 둘 다 필요 없다"고 명시.
  • Fast mode(/fast on, service_tier = "fast"): 속도 1.5배, 크레딧 2.5배 차감. API에서는 정가 2배. 토큰을 아끼는 기능이 아니라 쓰는 기능입니다.

4. 토큰 처리 내부 구조

4.1 요청 한 번에 들어가는 토큰

에이전트 코딩 도구(Claude Code, Codex)는 사용자가 메시지 하나를 보낼 때 API 요청을 여러 번 보냅니다. 매 툴 호출마다 대화 전체가 다시 입력으로 들어가므로, 세션 후반의 요청 하나는 다음으로 구성됩니다.

[시스템 프롬프트 + 툴 정의 + CLAUDE.md/AGENTS.md + 스킬 요약]   ← 매번 동일, 캐시 대상
[이전 대화 전체: 사용자 메시지, 모델 응답, 툴 호출, 툴 결과]     ← 계속 커짐
[이번 턴의 새 입력]                                             ← 캐시 미적중 부분
────────────────────────────────────────
출력 = thinking/reasoning 토큰 + 텍스트 + 툴 호출 인자

따라서 비용을 지배하는 변수는 세 가지입니다. (1) 프리픽스가 캐시에 얼마나 맞는가, (2) 대화 히스토리가 얼마나 커졌는가, (3) 출력(특히 추론) 토큰이 얼마나 나오는가.

4.2 추론(thinking / reasoning) 토큰 과금

Claude

  • Thinking 토큰은 출력 단가로 과금. 이전 턴의 thinking 블록이 컨텍스트에 남으면 그다음 요청부터 입력 토큰으로 다시 과금.
  • Opus 4.5+ / Sonnet 4.6+ / Fable은 이전 thinking을 기본 유지. 이하 모델과 Haiku는 마지막 턴만 유지.
  • effort는 thinking 양뿐 아니라 텍스트·툴 인자까지 전체 응답 토큰에 영향. low는 단순 작업에서 thinking을 건너뜀.
  • Opus 5.5·Fable은 thinking을 끌 수 없음. Claude Code 공식 문서: "기본 예산이 요청당 수만 토큰이 될 수 있다".
  • effort 값을 바꾸면 프롬프트에 렌더링되므로 캐시 브레이크포인트가 무효화됨. 세션 중간에 자주 바꾸지 말 것.

Codex / OpenAI

  • Reasoning 토큰은 API로 볼 수 없지만 컨텍스트를 차지하고 출력 단가로 과금.
  • reasoning.effort = none / low / medium / high / xhigh / max. Astra는 none 불가.
  • reasoning.mode: "pro"는 여러 번 돌린 작업량을 합산 과금. Codex의 Max/Ultra도 같은 원리.
  • 공식 권고: 추론+출력용으로 최소 25,000토큰 여유를 남길 것. 부족하면 incomplete 상태로 끝남.
  • GPT-6는 configuration_update 입력 항목으로 응답 사이에 effort 변경 가능. Codex CLI에서는 model_reasoning_effort, plan 모드는 plan_mode_reasoning_effort로 분리 설정.

실전 효과 예시(Opus 5.5, 평균 컨텍스트 100K, 20턴): 캐시 없음 2M 입력 × $4 = $8.00. 캐시 적중률 90%라면 0.2M × $4 + 1.8M × $0.20 = $1.16. 입력 비용이 약 1/7로 줄어듭니다. 캐시 무효화를 일으키는 행동(툴 정의 변경, effort 변경, 시스템 프롬프트 앞부분 수정)을 피하는 것이 절감의 핵심입니다.

4.4 컴팩션(대화 요약 압축)

Claude

  • Claude Code: 1M 네이티브 모델은 약 967K에서 자동 컴팩트. /autocompact 500k, CLAUDE_CODE_AUTO_COMPACT_WINDOW, CLAUDE_AUTOCOMPACT_PCT_OVERRIDE로 더 이르게 설정 가능(100K~1M).
  • /compact 코드 샘플 위주로처럼 지시문 전달 가능. CLAUDE.md에 # Compact instructions 섹션으로 고정.
  • 컴팩션 자체가 "대화 전체를 읽는 큰 요청"이라 완전 무료가 아님. 새 주제면 /clear가 가장 쌈(0원).
  • API: compact_20260112(기본 150K, 최소 50K 트리거)와 온디맨드 compaction: summarize. 요약 토큰은 전액 과금, 요약 블록 재전송은 무료.
  • clear_tool_uses_20250919로 오래된 툴 결과만 서버에서 지우기(기본 100K 초과 시, 최근 3개 유지).

Codex / OpenAI

  • Codex CLI: model_auto_compact_token_limit로 임계값 지정, compact_prompt로 요약 지시문 교체. tool_output_token_limit로 툴 출력 저장 상한.
  • features.rollout_budget.limit_tokens로 세션 토큰 예산을 걸고 10%마다 리마인더.
  • API: context_management: [{type:"compaction", compact_threshold: 200000}]로 서버 측 자동 압축. 암호화된 compaction item으로 상태 전달. POST /responses/compact로 수동 압축.
  • 272K를 넘기면 요청 전체가 롱 컨텍스트 요금이므로, 컴팩트 임계값을 272K 아래(예: 200K)로 두는 것이 비용상 중요.

4.5 서브에이전트

양쪽 모두 서브에이전트는 자체 컨텍스트에서 툴 작업을 하고 요약만 부모에게 돌려줍니다. 부모 컨텍스트가 툴 출력으로 부풀지 않아 이후 모든 턴의 입력 토큰이 줄지만, 서브에이전트 자체가 토큰을 쓰므로 총량은 늘 수 있습니다. 절감의 조건은 서브에이전트를 더 싼 모델로 돌리는 것입니다.

Claude Code

  • 에이전트 frontmatter model: haiku / effort: low.
  • CLAUDE_CODE_SUBAGENT_MODEL=haiku(범용 에이전트), _FORCE로 frontmatter까지 덮어쓰기.
  • 내장 Explore는 부모 모델을 상속하되 Opus 상한. Plan은 상속.
  • 에이전트 팀은 플랜 모드에서 약 7배 토큰. 팀원은 Sonnet 권장.

Codex

  • [agents] default_subagent_model = "gpt-6-luna", default_subagent_reasoning_effort.
  • 내장 default / worker / explorer. ~/.codex/agents/*.toml로 역할별 모델 지정.
  • max_concurrent_threads_per_session으로 병렬 수 제한.
  • 공식 권고: "서브에이전트는 원시 출력 대신 요약을 반환하게 할 것".

4.6 구독 vs API: 무엇이 차감되는가

Claude 구독 (Pro / Max 5x / Max 20x)

  • 5시간 롤링 창 + 주간 창. claude.ai 채팅, Claude Code, Cowork가 같은 한도를 씁니다.
  • Pro $20 → Claude Code 5시간당 약 10~40 프롬프트. Max 5x $100 → 50~200, Max 20x $200 → 200~800(공식 지원 문서 추정치).
  • Fable: Max는 주간 한도의 50%까지, Pro는 별도 크레딧.
  • 모델 계열별 한도 메시지("Opus 한도 도달")가 따로 있어 Opus 한도에 걸려도 Sonnet으로 전환하면 계속 작업 가능.
  • 캐시 적중 토큰은 한도를 덜 차감.

ChatGPT 구독 (Plus / Pro)

  • 5시간 창 + 주간 창. 크레딧 환산율(100만 토큰당): Luna 2.5 / 0.25(캐시) / 12.5(출력), Sol 50 / 5 / 250, Astra 250 / 25 / 1,250.
  • Plus 5시간당 로컬 메시지 추정: Astra 5~45, Sol 15~150, Luna 350~3,000. Pro(5x) 25~225 / 70~700 / 1,750~14,000.
  • Fast mode는 GPT-6 전 모델 2.5배 차감. 클라우드 채팅은 GPT-5.6 Sol을 써서 더 많이 차감.
  • API 키 로그인 시 크레딧이 아닌 API 정가.

5. 절감 원칙 10가지

  1. 모델을 작업 크기에 맞춘다. 주력 모델(Opus 5.5 / Sol)을 기본으로 두고, 확실히 어려운 것만 상위로, 반복적인 것은 하위로 내린다. Fable·Astra는 "주력 모델이 실패했을 때"의 카드다.
  2. effort를 낮춘다. Claude /effort low, Codex Light/Low. 출력 토큰의 대부분이 추론이며, 단순 작업에서 low는 추론을 아예 건너뛴다.
  3. 캐시를 깨지 않는다. 툴 정의, 시스템 프롬프트 앞부분, effort 값을 세션 중간에 바꾸지 않는다. MCP 서버 켜고 끄기도 툴 정의 변경이다.
  4. 새 주제는 새 세션. /clear(Claude), 새 스레드(Codex)는 0원. 컴팩션은 큰 요청 하나를 더 쓰는 것이다.
  5. 컴팩트 임계값을 낮춘다. 1M 창을 다 채우면 마지막 100턴이 매번 90만 토큰을 입력한다. Claude Code /autocompact 300k, Codex model_auto_compact_token_limit = 200000(272K 롱 컨텍스트 요금 회피).
  6. 툴 출력을 미리 거른다. 테스트 로그 전체 대신 실패만, git diff 대신 --stat. Claude Code는 PreToolUse 훅으로 필터링, Codex는 tool_output_token_limit.
  7. MCP를 줄이고 CLI를 쓴다. MCP 툴 정의는 매 요청 입력에 실린다. gh, aws, gcloud 같은 CLI가 대부분 더 싸다. 안 쓰는 MCP 서버는 /mcp에서 끈다.
  8. 탐색과 검증은 경량 서브에이전트로. Haiku / Luna 서브에이전트가 파일을 읽고 요약만 돌려주면 부모 컨텍스트가 깨끗하게 유지된다.
  9. CLAUDE.md / AGENTS.md는 200줄 이하. 긴 지침은 스킬로 옮겨 필요할 때만 로드한다. Codex는 skills.max_context_tokens가 기본 컨텍스트의 2%.
  10. 시간에 덜 민감하면 Batch. 양쪽 모두 50% 할인. 캐싱과 중복 적용된다. OpenAI Flex도 Batch 요율.

6. 시나리오별 최소 토큰 조합

각 시나리오는 "품질을 유지하면서 가장 적게 쓰는 조합"을 기준으로 골랐습니다. 구독 사용자는 정가 대신 한도 차감으로 읽으면 됩니다. 절감률은 주력 모델 기본 설정 대비 대략적인 추정치입니다.

S1. 단일 파일 버그 수정, 오타·타입 오류, 소규모 수정

문제 위치가 명확하고 컨텍스트가 작은 작업. 하루에 가장 많이 발생한다.

Claude

/model sonnet + /effort low. 파일을 @경로:줄범위로 직접 지정해 탐색 툴 호출을 없앤다.

비용 감각: Sonnet 5 low는 Opus 5.5 medium 대비 입력 1/2, 출력 1/2에 추론 토큰도 대폭 줄어 약 70~80% 절감.

Codex

codex -m gpt-6-luna + effort high, 또는 Sol Light. 파일과 줄을 프롬프트에 명시.

비용 감각: Luna는 Sol의 1/20 단가라 effort를 high로 올려도 약 90% 절감. 결과가 미덥지 않을 때만 Sol Light로.

왜: 이 작업의 토큰은 거의 전부 "불필요한 탐색"과 "불필요한 추론"에서 나온다. 위치를 알려주고 effort를 내리면 둘 다 사라진다.

S2. 중간 규모 기능 구현 (2~10개 파일, 테스트 포함)

설계 판단이 조금 필요하지만 아키텍처를 바꾸지는 않는 일상적 개발.

Claude

/model opusplan: 플랜 모드는 Opus 5.5, 실행은 Sonnet 5. 플랜을 승인한 뒤 실행 단계는 /effort medium.

또는 Opus 5.5 단일 사용 시 기본 medium 유지. 테스트 실행 출력은 훅으로 실패만 남긴다.

약 40~50% 절감(Opus 전 구간 대비).

Codex

Sol Medium(기본)로 시작. 플랜 단계만 plan_mode_reasoning_effort = "high", 실행은 model_reasoning_effort = "medium".

탐색은 explorer 서브에이전트를 default_subagent_model = "gpt-6-luna"로.

약 30~40% 절감(Sol High 전 구간 대비).

왜: 생각이 필요한 순간은 계획을 세울 때이고, 계획이 나온 뒤의 실행은 상대적으로 기계적이다. 단계별로 모델·effort를 나누면 비싼 토큰이 계획에만 쓰인다.

S3. 대규모 리팩터링·아키텍처 변경 (수십 파일, 모듈 경계 재설계)

잘못 설계하면 재작업 비용이 토큰 비용보다 훨씬 크다. 여기가 최상위 모델의 자리다.

Claude

1단계: Fable 5.1 high로 플랜 모드에서 설계 문서와 파일별 변경 목록만 작성(구현 금지). 2단계: /clear 후 Opus 5.5 medium이 그 문서를 읽고 실행. 3단계: 검증은 Sonnet 5 서브에이전트.

Max 플랜은 Fable이 주간 50%까지라 1단계에만 쓰는 것이 맞다. Pro는 Fable 대신 Opus 5.5 xhigh.

Codex

1단계: Astra Light(low)로 설계 문서 작성. Astra는 low에서도 판단력이 유지되므로 굳이 Medium 이상으로 올리지 않는다. 2단계: 새 스레드에서 Sol Medium이 실행. 3단계: Luna 서브에이전트가 테스트·린트.

Ultra는 병렬화 가능한 독립 작업이 실제로 있을 때만.

왜: 최상위 모델의 출력 단가는 주력의 5배지만, 설계 단계는 출력이 짧다(문서 몇 천 토큰). 실행 단계는 출력이 길다(코드 수만 토큰). 비싼 모델을 짧은 출력 단계에만 배치하면 총비용의 대부분을 주력 모델 단가로 처리하게 된다.

S4. 코드 리뷰 / PR 리뷰

읽기 전용, 출력은 짧은 지적 목록. 입력이 크고 출력이 작은 전형적인 케이스.

Claude

Sonnet 5 medium. diff만 넘긴다(gh pr diff 123 | claude -p "리뷰"). 전체 파일을 읽게 두지 않는다.

반복 리뷰(CI 등)는 API Batch로 50% 추가 할인.

Codex

codex exec -m gpt-6-sol "Review the current changes"에 effort low. 사소한 스타일 리뷰는 Luna high.

GitHub 연동 Code Review는 별도 사용량으로 잡히니 로컬 exec가 더 예측 가능.

왜: 리뷰의 품질은 모델 크기보다 "무엇을 보여줬는가"에 좌우된다. diff만 주면 입력이 1/10로 줄고, 출력은 원래 짧다.

S5. 코드베이스 탐색·질문 ("이 함수 어디서 호출돼?", "인증 흐름 설명해줘")

파일을 많이 읽지만 답은 짧다. 읽은 내용이 부모 컨텍스트에 남으면 이후 모든 턴이 비싸진다.

Claude

Explore 서브에이전트에게 위임(자동으로 사용됨). CLAUDE_CODE_SUBAGENT_MODEL=haiku로 범용 에이전트를 Haiku로. 부모는 Sonnet 5.

탐색 결과 요약만 부모에 남으므로 이후 턴의 입력이 수십 K가 아니라 수 K.

Codex

explorer 서브에이전트를 Luna로 고정. 질문 자체는 Sol Light. Astra 실험 컨텍스트 관리(이전 툴 결과 검색)는 이 시나리오에서 유용하지만 Astra 단가를 감수해야 한다.

왜: 탐색 비용은 "읽은 파일 × 이후 턴 수"로 곱해진다. 서브에이전트로 격리하면 곱셈이 덧셈이 된다.

S6. 대량 반복 작업 (100개 파일 마이그레이션, 로그 분류, i18n 문자열 추출)

패턴이 정해져 있고 건수가 많다. 단가 × 건수라서 모델 단가가 그대로 비용이 된다.

Claude

Haiku 4.5(API) 또는 Sonnet 5 low. 공통 지시문+예시를 4,096토큰 이상으로 만들어 캐시가 걸리게 하고(Haiku 최소 길이), 1시간 TTL. 시간 여유가 있으면 Batch API로 50% 할인.

정가 예: 1,000건 × (입력 5K + 출력 1K) = Haiku 기준 약 $10, Batch면 $5.

Codex

Luna medium, codex exec로 스크립트화. 같은 프리픽스가 자동 캐시(30분 TTL)되도록 지시문을 앞에, 가변 내용을 뒤에.

정가 예: 같은 1,000건이 Luna 기준 약 $1, Batch면 $0.50.

왜: 반복 작업은 "가장 싼 모델이 통과하는가"를 10건으로 먼저 검증하고 나머지를 돌리는 것이 정석이다. 실패 건만 상위 모델로 재처리한다.

S7. 장시간 자율 에이전트 (밤새 돌리기, 수백 턴)

턴 수가 많아 컨텍스트 크기와 캐시 적중이 비용의 전부다.

Claude

Opus 5.5 medium(서버 컨텍스트 관리가 thinking을 무효화하지 않아 캐시 유지에 유리). /autocompact 300k로 이르게 압축, CLAUDE.md에 컴팩트 지시문 고정. 구독이면 캐시 1시간이라 유리.

API 직접 호출 시 clear_tool_uses_20250919 + compact_20260112 조합.

Codex

Sol medium. model_auto_compact_token_limit = 200000(272K 롱 컨텍스트 요금 회피), features.rollout_budget.limit_tokens로 상한. Fast mode 끄기(features.fast_mode = false, 2.5배 차감 방지).

왜: 500턴 세션에서 컨텍스트를 300K로 유지하면 총입력 150M, 900K로 두면 450M이다. 캐시가 90% 맞아도 절대량이 3배 차이난다.

S8. 문서·주석·테스트 생성

출력이 길고 추론은 거의 필요 없다. 출력 단가가 낮은 모델이 이긴다.

Claude

Sonnet 5 low. 출력 $10. 형식 예시를 프롬프트에 넣어 재작업을 없앤다.

Codex

Luna medium. 출력 $0.50. 긴 문서라도 부담이 없다.

왜: 이런 작업에서 상위 모델을 쓰면 추론 토큰이 붙어 출력이 오히려 길어진다.

실용적인 조합 제안

  • VS Code 또는 Cursor 한 창에서 둘 다: Claude Code 확장과 Codex 확장을 나란히 설치하면 같은 워크스페이스에서 두 구독을 번갈아 쓸 수 있습니다. Cursor 자체 AI 기능은 끄고 두 확장만 쓰면 Cursor 구독이 필요 없습니다.
  • JetBrains 사용자: Claude는 Anthropic 플러그인, Codex는 AI Assistant 내장 기능. 둘 다 추가 결제 없이 기존 구독으로 동작합니다.
  • 터미널 중심: tmux로 Claude Code와 Codex를 나란히 띄우고 역할을 나누는 방식이 가장 유연합니다. 설계·리뷰는 한쪽, 실행은 다른 쪽처럼 두 구독 한도를 합산해 쓰는 효과가 있습니다.
  • 주의: Claude 구독은 claude.ai 채팅, Claude Code, Cowork, Xcode 채팅이 한 한도를 씁니다. IDE에서 Claude Code를 많이 쓰면 채팅 한도도 같이 줄어듭니다.
