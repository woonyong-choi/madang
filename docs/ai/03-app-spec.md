### 2.1 레이어 0: 페이지 (3열) — Notebook Navigator 100% 준수

레이어 0의 구조·조작·세부 기능은 Obsidian 플러그인 **Notebook Navigator**(johansan/notebook-navigator)를 기준으로 그대로 옮긴다(ADR D18). 앱 팀은 이 기준에서 벗어나는 디자인 결정을 하지 않는다. 판단이 필요하면 Notebook Navigator가 어떻게 하는지를 먼저 확인한다.

개념 매핑:

| Notebook Navigator | Madang | 비고 |
|---|---|---|
| Vault | 앱 홈 | |
| Folder (계층) | Space | 하위 공간 허용. 공간 아이콘·색 지정 |
| Folder note | `space.md` | 공간을 클릭하면 본문 자리에 space.md가 열린다 |
| Tag (계층 `#a/b`) | Page tag | `page.md`의 tags. 태그 트리로 탐색 |
| Note | Page | |
| Note preview text | 페이지 마지막 메시지 한 줄 | |
| Feature image | 페이지의 첫 view 블록 썸네일 (없으면 없음) | |
| Note date | `updated` | |
| Pinned notes | `pinned: true` | 공간별 상단 고정 |
| Sort order per folder | 공간별 정렬 설정 | 갱신순 / 생성순 / 제목순 |
| Folder focus | 공간 포커스 | 그 공간과 하위만 표시 |
| Editor pane | 페이지 본문 (블록 흐름) | Notebook Navigator가 관여하지 않는 영역 |
| Quick actions on hover | 카드 hover: 고정, 태그, 이동, 삭제 | |
| Drag & drop | 페이지를 공간으로 끌어 이동, 태그로 끌어 태깅 | |
| Middle-click → new tab | 페이지를 새 창으로 | Phase B |
| Single / dual pane 모드 | 좁을 때 2열, 더 좁을 때 1열 | |
| Keyboard-first navigation | 화살표·Enter·Backspace로 열 이동과 열기 | §7 |

추가 표시 항목(Notebook Navigator에 없는 것)은 카드 안의 **상태 칩**(doing/blocked/review/done)과 **블록 종류 개수**뿐이며, 카드 레이아웃의 다른 부분은 바꾸지 않는다.

```
┌──────────┬────────────────────┬──────────────────────────────┐
│ 공간      │ 페이지 목록           │ 페이지 본문                    │
│          │                    │                              │
│ 루트      │ ┌────────────────┐ │ [message] 이력서 템플릿…       │
│ 지원  ●   │ │ 이력서   doing  │ │ [run] claude/opus-5-5 · 41K  │
│ auth-svc │ │ 요약문 다듬기…   │ │ [view] 이력서  (축소 렌더링)   │
│ blog     │ │ ▪ view 1 data 2 │ │ [data] base.json             │
│          │ ├────────────────┤ │ [message] 펄어비스용…          │
│ 태그      │ │ 공고 분석 review│ │ [run] codex/gpt-6-luna · 0.4K│
│ #이력서   │ │ 기술 일치 8/10  │ │                              │
│ #버그     │ └────────────────┘ │ ┌──────────────────────────┐ │
│          │                    │ │ 페이지에게…  ~31K  [보내기]│ │
│ + 공간    │ + 페이지            │ └──────────────────────────┘ │
└──────────┴────────────────────┴──────────────────────────────┘
```

**1열: 공간.** 공간 목록, 태그 목록. 공간 옆 점은 진행 중(doing/blocked) 페이지가 있음. 아래에 "+ 공간". 공간 클릭 → 2열 갱신. 우클릭: 이름 변경, 저장소 연결, 삭제.

**2열: 페이지 목록.** 카드 하나 = 페이지 하나. 표시: 제목, 상태 칩, 마지막 메시지 한 줄, 블록 종류별 개수, 마지막 실행 도구·모델, 갱신 시각. 정렬: 고정 → 갱신순. 필터: 상태, 태그. 아래에 "+ 페이지". 우클릭: 고정, 태그, 이동(다른 공간), 삭제.

**3열: 페이지 본문.** 블록이 시간순으로 세로로 쌓인다. 상단에 제목과 상태. 미등록 파일이 있으면 제목 아래에 노란 띠. 아래에 입력창.

블록의 본문 표현:

| 종류 | 본문에서 | 접힘 |
|---|---|---|
| message (user) | 오른쪽 정렬 말풍선 | 오래되면 접힘 |
| message (router) | 회색 점선 한 줄: 종류, 확신, 도구/모델 | 접힘 |
| message (agent) | 왼쪽 세로선 + 텍스트 (md 렌더) | 오래되면 접힘 |
| run | 한 줄 카드: 도구/모델 칩, 입력·출력 토큰, 소요, 바뀐 파일 수. 클릭 → 레이어 1 | 접힘 |
| doc | md 렌더 (mermaid 포함), 높이 상한 후 "더 보기" | 안 접힘 |
| data | 표 형태 미리보기 (json 최상위 배열/객체), 행 수 | 안 접힘 |
| view | 템플릿 실제 렌더링을 축소(가로 맞춤, 높이 상한). 클릭 → 레이어 1 | 안 접힘 |
| code (C) | 경로 + diff 요약 | 안 접힘 |
| term (C) | 명령 + 상태 + 마지막 5줄 | 안 접힘 |
| site (C) | URL + 스크린샷 | 안 접힘 |

"접힘"은 페이지가 문서로서 읽히도록 하기 위한 것이다. 접힌 블록은 한 줄로 줄고, 클릭하면 펼쳐진다. "모두 펼치기" 토글이 있다.

**입력창.** 대상 표시("페이지에게"), 텍스트, 다음 호출 입력 토큰 추정(`GET /preview-input`을 300ms 디바운스로), 보내기. Enter 보내기, Shift+Enter 줄바꿈. 접두 `design:` 등은 자동완성.

### 2.2 가운데 열: 탭 작업 공간 (레이어 1 오버레이를 대체)

블록을 클릭하면 본문 위로 떠오르는 대신 **가운데 열의 새 탭**으로 열린다. 탭과 분할의 조작은 Orca의 tabs/panes 모델을 따른다(ADR D21).

- 첫 탭은 항상 "페이지"(대화와 블록이 세로로 쌓인 문서 흐름). 닫을 수 없다.
- 문서 안의 view, doc, data, code, term, site, run 블록을 클릭하면 같은 이름의 탭이 열린다. 이미 열려 있으면 그 탭으로 이동.
- 탭을 가운데 열의 오른쪽 가장자리로 끌면 좌우 분할, 아래 가장자리로 끌면 상하 분할. 분할은 중첩된다. 활성 탭에는 색 막대.
- 탭 묶음과 분할 상태는 **페이지마다** 기억된다. 페이지를 바꾸면 탭 세트가 통째로 바뀐다.
- 탭 안 오른쪽 서랍(접을 수 있음)에 그 블록의 패널: view는 보기/편집 토글·슬롯과 연결·프리셋·템플릿·원본·승격·삭제, doc은 원본/미리보기·승격, data는 표 편집기/원본·이 데이터를 쓰는 뷰, run은 입력 구성·사용량·바뀐 파일·이벤트 로그, code는 diff/전체·외부 편집기, term은 명령·cwd·재실행, site는 URL·프로필.
- 연결 조작(슬롯에 데이터 끌어다 놓기, 프리셋 전환)은 view 탭의 서랍에서 한다. 규칙은 이전과 같다.
- 입력창은 가운데 열 아래 하나. 대상은 활성 탭이다: "페이지" 탭이면 페이지에게, 블록 탭이면 그 블록에게, 편집 모드에서 요소를 고르면 요소에게.
- 단축키: 탭 닫기 Cmd-W, 다음/이전 탭 Cmd-Shift-]/[, 좌우 분할 Cmd-\\, 상하 분할 Cmd-Shift-\\, 페이지 탭으로 Cmd-1.
- Esc: 편집 모드 선택 해제 → 편집 모드 종료 → 페이지 탭으로.

탭은 화면의 배치일 뿐이다. 탭으로 연 터미널·사이트·뷰는 페이지 폴더의 블록 파일이며, 탭을 닫아도 블록은 남는다(원칙 1·2).

v0.1 범위: 페이지 탭 + doc·data·run 탭. 분할은 v0.2. view·code·term·site 탭은 각 블록이 도입되는 단계에서.

### 2.4 레이어 2: 요소 선택 (view 탭의 편집 모드)

```
│ 화면 안: [경력 2 · 펄어비스] 에 하이라이트 테두리                   │
│ 패널:  선택 요소                                                 │
│          텍스트   [펄어비스          ]  ← 직접 수정 → data 저장    │
│          출처    base.json › work[1].company                     │
│          스타일   color.accent [#3a5bd9]  (템플릿 editable만)       │
│ 입력창: [경력 2 · 펄어비스 ×]  펄어비스 경력을 맨 위로 …   [보내기]  │
```

- 클릭: 선택 교체. Ctrl/Cmd+클릭: 추가. Esc: 해제.
- 텍스트와 editable 스타일은 패널에서 직접 고친다. 저장은 데이터 파일(`PUT block`)과 theme(`PATCH view`)로. AI 없음.
- 입력창으로 보낸 요청은 `target: {block, elements: [paths], mode: edit}`. core는 선택 요소의 HTML 조각 + 데이터 경로만 조립한다. 종류는 small 고정.
- 요소가 데이터에 연결되지 않은 부분(템플릿 고정 텍스트)이면 출처가 "템플릿"으로 뜨고, 수정 요청은 템플릿 수정 요청이 된다(Phase B: 템플릿 버전 올리기 흐름).

## 5. WebView 브리지 (`madang.js`)

WebView 안에서 도는 런타임. 템플릿과 md 렌더링 둘 다 이걸 쓴다.

앱 → WebView:
- `render(template, data, theme, mode)`
- `setMode('view'|'edit')`
- `select(paths[])`, `clearSelection()`
- `patchData(path, value)` (패널에서 직접 수정 시 즉시 반영)

WebView → 앱:
- `ready`
- `selected {paths, rects, htmlFragment}`
- `hover {path}`
- `navigate {url}` (보기 모드 링크. 앱이 외부 브라우저로)
- `error {message}`

역추적: `madang.js`가 렌더 시 각 요소에 `data-madang-path`를 붙인다. 클릭 시 가장 가까운 조상의 경로를 보고한다. 반복(`data-each`)은 인덱스를 경로에 넣는다(`work[1].company`).

보안: WebView는 페이지 폴더의 `file://`만. CSP로 외부 로드 차단. 템플릿 스크립트 금지(Phase F 전).

## 6. 상태와 이벤트 처리

- 앱은 시작 시 공간·페이지 목록을 받고, 이후 WebSocket 이벤트로만 갱신한다. 연결이 끊기면 재연결 후 전체 재조회.
- 낙관적 갱신은 입력창 메시지 추가와 블록 순서 변경만. 나머지는 이벤트를 기다린다.
- run 진행 중 표시: 본문 끝에 진행 카드(도구/모델, 경과 시간, 마지막 이벤트 요약). 취소 버튼 → `POST cancel`.
