# Madang: 결정 기록 (ADR)

상태: 초안 (AI 작성, 미승인)
작성: 2026-09-24

형식: 번호, 결정, 이유, 버린 대안, 되돌릴 조건. 결정이 바뀌면 새 번호로 쓰고 옛 것에 "대체됨"을 단다.

## D01. 이름은 Madang
- **결정.** 제품·저장소·CLI 이름을 `madang`으로 한다.
- **이유.** 일이 벌어지는 열린 공간이라는 뜻이 제품과 맞고, 국내 사용자에게 직관적이며, 영문 표기가 쉽고, GitHub·PyPI에 비어 있다.
- **확인 결과 (2026-09-24).** GitHub `woonyong-choi/madang` 사용 가능. PyPI `madang` 사용 가능. npm `madang`은 이미 있음(스코프 `@madang/*` 또는 `madang-app` 사용). `madang.dev/.app/.io`는 A 레코드 있음. `getmadang.com`, `madang.sh`는 A 레코드 없음.
- **버린 대안.** Empty(검색 불가, 오류 메시지처럼 들림), Tabula·Vivum·Slate(직관성 부족), Livepage(직관적이나 일반 단어 조합).

## D02. 문서 폴더는 `docs/`, AI 초안은 `docs/ai/`
- **결정.** 승인된 문서는 `docs/` 바로 아래. AI가 쓴 초안은 `docs/ai/`. 승인은 사람이 파일을 `docs/`로 옮기는 git 커밋으로 표현한다.
- **이유.** `docs/`는 GitHub Pages와 대부분 프로젝트의 관례라 도구 지원이 좋다. 초안을 같은 트리 아래 두면 git 이력에서 "초안 → 승인"의 이동이 한 커밋으로 남는다.
- **버린 대안.** `doc/`(관례 아님), 루트 `ai/`(문서와 초안이 다른 트리라 이동 이력이 흩어짐).
- **규칙.** `docs/ai/` 파일 머리에 "상태: 초안 (AI 작성, 미승인)"을 둔다. `docs/`로 옮길 때 그 줄을 지운다. `docs/ai/reference/`는 조사·목업 자료로, 승격 대상이 아니다.

## D03. 앱은 Kotlin, core는 Python
- **결정.** 화면은 Kotlin Multiplatform + Compose Multiplatform. 흐름·실행·저장은 Python(FastAPI, LangGraph).
- **이유.** Kotlin은 사용자 선택이며 macOS·Windows·Android·iOS를 한 코드로 간다. LangGraph는 Python 네이티브이고 interrupt·체크포인터·스트리밍이 필요하다. core는 어차피 에이전트 CLI를 subprocess로 띄우는 로컬 프로세스라 언어가 달라도 경계 비용이 없다.
- **버린 대안.** 전부 Kotlin(LangGraph4j 등은 공식 구현이 아님, 체크포인터·interrupt 성숙도 낮음). 전부 Python(데스크톱·모바일 앱 품질 한계).
- **되돌릴 조건.** LangGraph 의존이 사라지고 흐름이 단순 상태 기계로 충분해지면 core를 Kotlin으로 옮길 수 있다. 경계가 OpenAPI라 앱은 영향 없음.

## D04. 앱과 core의 경계는 OpenAPI 하나
- **결정.** `core/openapi.yaml`이 계약의 진실. Kotlin 클라이언트는 생성. 이벤트는 WebSocket, 스키마는 같은 파일에 정의.
- **이유.** 두 언어를 한 계약으로 묶어야 서로의 내부를 모른 채 발전한다.

## D05. core가 단일 작성자
- **결정.** 앱 홈 폴더에 쓰는 프로세스는 core뿐. 앱은 API, 에이전트는 `madang` CLI(→ API).
- **이유.** 불변조건(블록 순서, 등록, 상한, 커밋 단위)을 한곳에서 지킨다. 동시 쓰기 충돌이 없다.
- **비용.** 앱이 파일을 직접 못 읽어 API 왕복이 늘어난다. 로컬이라 감수.

## D06. 앱 홈은 git 저장소
- **결정.** `~/.madang/`을 비공개 git 저장소로. run·편집·삭제 단위로 core가 커밋. 원격은 선택.
- **이유.** 삭제해도 이력에 남고, 되살리기가 표준 도구로 되고, 기기 간 이동이 된다.
- **비용.** 민감정보가 이력에 남을 수 있음 → Phase D 커밋 전 필터와 완전 삭제.
- **버린 대안.** SQLite 단일 파일(사람이 열어볼 수 없음), 코드 저장소 안에 두기(저장소 오염).

## D07. 에이전트는 CLI로, 매번 새 세션
- **결정.** Claude Code와 Codex를 API가 아닌 CLI(`claude -p`, `codex exec`)로 호출한다. 세션을 이어 쓰지 않는다.
- **이유.** 사용자 구독을 그대로 쓴다. 세션을 버리면 입력이 고정 크기로 유지되고, 메모리가 파일로 보인다.
- **비용.** 이전 대화의 프롬프트 캐시 이득을 포기. 대신 시스템 프롬프트와 지시문은 캐시된다.
- **되돌릴 조건.** 없음. 원칙 6.

## D08. 부작용은 `madang` CLI로만
- **결정.** 커밋·푸시·삭제·승격·결정 기록은 에이전트가 `madang` 명령으로 요청. 날것의 `git push`, `rm -rf`는 권한 규칙으로 거부 권고.
- **이유.** 위험 판단을 모델이 아니라 앱 코드에 둔다. 모든 부작용이 로그에 남는다. 권한 규칙이 한 줄(`madang *`)로 끝난다.
- **비용.** 에이전트 지시문에 명령 목록(약 300토큰)이 붙는다.

## D09. AI는 데이터만, 표현은 템플릿
- **결정.** 화면은 템플릿(HTML + data-bind) + 데이터(JSON). 에이전트는 HTML을 쓰지 않는다.
- **이유.** 토큰(수천 → 수백), 일관된 모양, 사람이 고치기 쉬움, 요소↔데이터 역추적 가능.
- **버린 대안.** 매번 HTML 생성(Claude 아티팩트 방식). 기존 템플릿 엔진(역추적 없음).

## D10. 렌더링은 WebView 하나
- **결정.** md, mermaid, 템플릿 모두 WebView 안의 `madang.js`로 그린다. 데스크톱은 KCEF.
- **이유.** 플랫폼 간 같은 결과. 템플릿이 웹 표준이어야 커뮤니티가 가능.
- **비용.** KCEF 배포 크기(약 100MB). 감수.

## D11. 레이어, 분할 아님
- **결정.** 화면은 레이어 0(3열 페이지) → 1(블록 초점) → 2(요소 선택). 입력창은 하나, 대상만 바뀐다. 파일 트리는 없다.
- **이유.** 채팅과 화면이 서로를 모르는 분할 화면의 불편을 없앤다. 탐색 계층을 하나로 유지한다.

## D12. 레이어 0은 3열
- **결정.** 공간 / 페이지 목록(미리보기 카드) / 페이지 본문. Notebook Navigator식.
- **이유.** 페이지가 많아져도 트리가 길어지지 않고, 카드에 작업 상태를 담을 수 있다.

## D13. 뷰 블록에 보기/편집 모드
- **결정.** 편집 모드에서만 요소 선택·직접 수정·대화 수정이 켜진다. 보기 모드는 템플릿의 원래 동작.
- **이유.** 같은 클릭이 두 뜻을 가지면 안 된다(한 동작 한 기능).

## D14. 첫 목표는 Phase A = 화면까지
- **결정.** 원래 0·1단계에 뷰 블록과 편집 모드를 앞당겨 넣어 Phase A로 한다.
- **이유.** 사용자가 "실제로 쓰는 도구"라고 느끼려면 빌드된 화면 조작이 있어야 한다는 사용자 판단.

## D15. 서비스는 별도 실행기, 구독 공유 없음
- **결정.** 로컬은 사용자 본인 구독 CLI, 서비스는 운영자 API 키 + 크레딧. 한 프로세스에서 섞지 않는다.
- **이유.** 소비자 구독 약관. 앱 구조는 Runner 구현체만 다르다.

## D16. 라이선스 MIT
- **결정.** 저장소는 MIT.
- **이유.** 개발자 도구의 관례. 서비스 부분(Phase F)은 별도 저장소로 갈 수 있다.
- **되돌릴 조건.** 서비스 방어가 필요해지면 core를 AGPL로 바꾸는 것을 검토. 초기 사용자 확보가 우선.
